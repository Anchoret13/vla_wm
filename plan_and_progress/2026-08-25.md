### Execute the same improvement round twice

For `k in {0, 1}`:

1. Deploy full-prompt `N=1` `pi_k` on a fixed 107-source acquisition queue and
   retain the first **up to 48** eligible failures. Use queues `4300–4406` for
   round 0 and `4500–4606` for round 1. A smaller round-1 failure set is retained
   as an improvement outcome, not treated as an underfill halt.
2. At each failure anchor, construct the unchanged supported five-candidate
   pool. Before any outcome is visible, `M_k` scores the four alternatives and
   selects its highest predicted `delta_QPhi` candidate.
3. Execute only the reference and that WM-selected candidate under four shared
   continuation keys. Every outcome joins the cumulative WM bank. A selected
   prefix becomes a verified VLA correction only when its executed mean `QPhi`
   is better than the reference and damage is non-inferior.
4. Train `M_{k+1}` on the cumulative bank using the same residual formulation
   and consequence objective. Then update `pi_k -> pi_{k+1}` from the current
   VLA checkpoint using demonstration rehearsal plus the verified first-ten
   action prefixes. The first closed loop uses executed corrections only; it
   does not train the VLA on unexecuted model guesses.
5. Evaluate `pi_{k+1}` with full-prompt `N=1` inference on the same frozen
   32-seed behavior panel `3200–3231`. Behavior episodes never enter WM or VLA
   training.
