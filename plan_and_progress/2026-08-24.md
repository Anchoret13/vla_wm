**The action-conditioned model loses to every baseline on every metric.** Three
readings that are each worth stating separately:

1. **The action path is used, and it hurts.** Shuffling actions moves the action
   model's loss by 0.0184 and leaves the baseline's at exactly 0. The model is
   conditioning on the action; conditioning is making it worse.
2. **Its candidate ranking is anti-correlated.** Effect correlation is
   **−0.2275**. It is not merely uninformative about which sibling is better —
   it is worse than uninformative, and top-1 regret is accordingly higher than
   just executing the reference.
3. **Neither model beats "assume every candidate equals the reference".** The
   copy/no-change baseline's effect MAE is **0.014041** against the action
   model's 0.063 and the state-only model's 0.036. Predicting the continuous
   consequence is harder than predicting no difference.

Note that `state_only` and `stock_reference` tie exactly on paired effect and
top-1 regret (0.014041 / 0.012647). That is by construction, not coincidence: a
model with no action input scores every candidate identically, so its predicted
delta is zero, which is the stock-reference predictor. The two registered
baselines are the same bar here.

Selection: validation chose epoch **4** for the action model and **27** for
state-only, before the test split was read. The action model peaks almost
immediately and then degrades — validation loss 0.90–0.96 at epochs 27–29
against the baseline's 0.49–0.69. With 48 training anchors and a target whose
signal-to-noise on the candidate mean is roughly 1.7×, it overfits the action
input fast.

## Two defects of mine, and what they cost

Both were in code I wrote for this action, and **both were caught by a number
looking wrong rather than by a test.**

### 1. The bank was anchored on the wrong population — 138,723 steps

The first collection released an anchor whenever the exact event mask matched at
`tau=160`, and never checked that the source episode **failed by step 250**.
Every prior action applies both conditions. **33 of 64 anchors came from
episodes that go on to succeed.**

The method is failure-anchored (framework §3), so training M0.2 on that bank
would have silently redefined the population the world model learns and broken
comparability with every earlier artifact — and it would not have shown up in
any training metric. The tell was the fill rate: 64 groups from 64 sources is
100% eligibility against a measured 0.538, and Action 2M.4's own ceilings
(108/23/23 for 48/8/8) are sized from that 0.538. The action item's arithmetic
contradicted my implementation.

Fix: release the anchor only when the source ends in `failure@250`. The snapshot
is still taken at `tau`; only the release moves to the deadline, where the
terminal outcome first exists.

### 2. A regression of my own cap fix — ~8,932 steps

The re-collection halted after three groups with `branch: worst case 80 vs
headroom 41`. I had built `SegmentLedger`'s quarantine list two actions earlier,
after Action 2M.3 attempt 2 hit exactly this failure — a superseded run's spend
eating its successor's cap. Then I invented a new label, `DISCARDED_`, that the
hardcoded list did not contain. **The list fails open.**

Fix: quarantine by regex on any ALL-CAPS label prefixed to a run stamp, verified
against an invented label to confirm a future one cannot slip through. The named
list is now documentation only.
