**The research object is a feedback chain with identifiable causal contributions.** Freeze the base VLA backbone, use actions and observations actually obtained during deployment to update a latent world model without reconstruction, then improve the next deployment through a small trainable policy interface. The research question is whether, under low baseline success and sparse feedback, correcting dynamics with new deployment data lets the next policy achieve higher success with fewer actual interactions, and whether that benefit repeats in later rounds. Here, “recursive” means feedback across rounds through parameters and the data distribution.

```text
Deploy π_r → new trajectories D_r → update M_r to M_{r+1}
    ↑                                      ↓
Deploy π_{r+1} ← improve the policy interface using predicted future states
```

Freezing the base backbone is compatible with updating a policy interface. The trainable parameter boundary must be explicit; freezing the interface as well would restrict the study to inference-time state updates or external selection. Data collected by the policy must in turn correct the model to establish the recursive mechanism of interest.

**Candidate architecture: feed predicted state into sustained control, with external selection as a comparison.**

The original proposal made intervention diagnostics a prerequisite for choosing this route; that prerequisite is superseded. A candidate structure preserves the frozen VLA's original observation path and adds a small, zero-initialized residual/action-expert interface. Belief uses only the current observation and previously executed actions. The future model receives candidate actions available at decision time and explicitly predicts future latents:

\[
b_t = F_\theta(b_{t-1}, E(o_t), a_{t-1}),\qquad
\hat z_{t+hc}=T_\theta^{(h)}(b_t,u_{t:t+hc-1}).
\]

Train on all actual success/failure segments, targeting actual future features. Start with a rollout loss at the registered execution time scale; optional time-scale diagnostics may guide later revisions. Introduce a distributional model or ensemble only if measured multimodal error or useful uncertainty motivates it; do not automatically copy TD-MPC's compression dimension or Dreamer's decoder. Supervised event/value heads may read from predicted latents, while the model's core prediction target remains future state.

This structure has an important interface constraint: a pooled latent is not the complete visual input expected by the original π0.5. Calling a small prior on predicted latents cannot be assumed equivalent to placing the frozen π0.5 inside imagination. Two possible approaches are faithful integration at a validated action-expert token boundary, or starting from an actual b_t and an executable short action chunk to construct policy targets at the current actual state through limited imagination, without treating synthetic latents as complete observations. If using a closed-loop option transition T(b,ω,h), ω must denote a specified executable sustained controller. That model predicts option consequences, not arbitrary primitive-action dynamics, and must not condition on future executed actions unavailable during deployment.

A lightweight interface can use validated multistep advantages for weighted learning or receive predictive belief. When chain3 lacks an improvement direction, BC or predictive loss alone does not automatically supply one. The original architecture comparison retained two families already present in the framework: external imagination for policy targets and internal predictive-state conditioning, without a large hyperparameter search. This is follow-up design space, not a requirement to implement both families before the approved small-interface loop. Earlier failures of internal interfaces remain evidence; a new variant must identify what information or supervision it adds.

**Another optional use: let the WM improve data collected in the next round.** Success is sparse on chain3, and the current policy repeatedly stops at similar stages. Given an executable behavior set, calibrated model disagreement over future latents could select sustained controllers for the next collection batch, targeting poorly understood consequences near the current failure frontier. The original proposal used a sustained-intervention diagnostic to establish that set; it is an optional source of evidence rather than a prerequisite for the approved loop. All candidates must come from controllers supported by actual deployment; the first version need not learn a large skill library. Compare WM-guided collection, random selection from the same candidates and base-policy collection, matching actual steps, starting distributions, labels and downstream training budgets.

For such an acquisition study, test whether disagreement predicts held-out consequence error and whether both disagreement and error fall after adding actual data. Earlier v200–v208 ensemble disagreement did not effectively distinguish base/residual behavior; changing the objective to exploration does not automatically make it reliable. Maximizing uncertainty alone may repeatedly visit uncontrollable noise. Train identical WM and policy updaters on each method's collected data, then compare next-round actual success. Greater coverage or lower disagreement alone does not constitute policy improvement.

Two causal paths require separate attribution:

```text
Control path: same D → updated WM → better policy update
Acquisition path: updated WM → more useful new D → better policy from the same learner
```

The control path requires a same-data model-free comparison. The acquisition path requires an equal-budget acquisition comparison: giving the same WM-selected data to a model-free method holds the data mediator fixed, so equal downstream performance cannot by itself refute a contribution from WM-guided acquisition. Keep both comparisons because they answer different questions. If an updated WM selects learnable sustained interventions better than a fixed WM, and their new data improve both model and policy, that also directly supports the project's recursive objective. This hypothesis is motivated by the project bottleneck and Plan2Explore's mechanism; it has not been validated under our conditions.

For the approved first loop, the required comparison is updated WM, stale WM and same-data model-free, using the same actual replay, a fixed feedback protocol and matched small-interface training budgets. Holding the feedback protocol fixed does not mean reward can never change; it isolates dynamics for the current comparison. Useful reports include forgetting on old states, task-event prediction on the new policy distribution, actual policy outcomes and same-state candidate ranking, with overall latent MSE as an auxiliary measure. Action shuffling is an ablation, not the sole source of evidence. A direct action-outcome scorer provides a stronger additional comparison than only using structurally damaged models. These extended diagnostics and ablations can follow the minimal result and do not expand its required initial arms.

A later system-level stage lets methods independently run π0→D0→M1→π1→D1→M2→π2. Each arm owns its deployment-data trajectory, with actual interaction and labeling costs matched. Shared-replay ablations from the first stage cannot substitute for this system-level comparison. Core comparisons include evolving WM, a WM fixed after the first round while its interface continues updating, an equal-budget model-free loop and a one-shot update with the same total interaction budget. Specify which fixed behavior policy collects the one-shot data; a post-hoc aggregation of final data cannot be treated as having the same information timing.

The eventual main plot should show success against cumulative actual interactions, supplemented by failure-stage changes, event-prediction error on the next-round distribution and gain per actual trajectory. If only first-round WM conditioning helps and later updates add no benefit, limit the claim to one-shot model assistance. The D0 milestone record (`results/v121_deploy_latents/chain3_lr2_2026-08-30T083910Z`,

|---|---|---|---|---|---|---|
| episodes /96 | 93 | 93 | 94 | 92 | **5** | 3 |
| median step | 70 | 140 | 210 | 260 | 460 | 594 |

A fresh instrumented rollout (seed 8704) shows what happens in that tail. After
placing the second can the end-effector parks at `[0.004, 0.259, 0.720]` — 29 cm
vertically above the basket at `[0.000, 0.266, 0.432]` — and stays. Its distance
to `cream_cheese_1` rises from 0.347 m at reset to a basin mean of **0.553 m**
(sd 0.009). The cream cheese is displaced by exactly 0.00000 m for the whole
episode. Per-chunk EEF motion in the basin is 2.6 mm.

This generalises across the whole panel. Using the proprioception block of the D0
tape (`z[:, 8192:8195]` is `robot_state.eef.pos`), 93/96 episodes have a basin of
at least 10 boundaries, and in it the median per-chunk EEF displacement is
**5.95 mm against 66.95 mm before the last milestone — 8.9%**. 80.6% of basins run
at under a fifth of the pre-stall motion rate.

So chain3 is not uniformly hard and the policy is not fumbling the third object.
It completes two of three sub-tasks reliably, retreats to a hover over the basket,
and stops issuing task-directed motion. The headroom is 490 wasted steps per

### Three candidate feedback signals are degenerate — including the expected one

Run before choosing a reward, per the rule that zero-cost diagnostics precede
candidates:

- **binary success**: 2/96. The independent power analysis gives a minimum
  detectable effect at n=96 of a 3.5x rate increase; n=192 is the first size at
  which a 2.5x effect is reliably detectable.
- **milestone index**: constant at 4 for 88/96 episodes; the whole 6-level
  distribution has ~8 informative episodes.
- **`lcwm/phase_potential.py` Φ**: expected to resolve *inside* the basin via its
  approach/grasp/lift/transport/placement decomposition. It does not. On the
  instrumented episode Φ is flat at exactly **2.0 for all 49 basin boundaries**.
  The cause is structural, not a bug: the approach term is
  `0.2 * (1 - clip(d_eef / start_eef_d))`, normalised by the episode's *own* start
  distance, so it clips to zero the instant the arm retreats further than it began —
  which is exactly what the stall does (0.347 m start, 0.553 m basin).

The dense, action-sensitive quantity that does vary in the basin is the unclipped
EEF-to-active-object geometry. A fixed task-scale normaliser instead of
`start_eef_d` restores a monotone signal, and it is a quantity a video annotator
can order ("is the gripper getting closer to the cream cheese"), which is what the
approved fixed-budget stage feedback permits. Any positive result must be scoped
to that supplied signal.

### Zero-step diagnostic: is `Phi'` readable from the latent, and where?

Run on the 24-episode base calibration arm (1,800 rows, 8217-d rich latent,
episode-disjoint 18/6 split) before any interface is trained. Rule 1 of the
placement-axis diagnosis: the supervised ceiling for the target quantity costs no
environment steps and would have explained four to five candidate failures.

**Globally, `Phi'` is mostly a clock.**

| probe | holdout rho |
|---|---|
| rich latent, 8217-d | +0.913 |
| visual block only (`z[:8192]`) | +0.927 |
| proprio block only (25-d) | +0.901 |
| **clock only (the scalar `t`)** | **+0.986** |
| label-shuffled control | +0.001 |

A nonlinear function of `t` alone explains **97.2%** of `Phi'` variance. This is
exactly the failure the 09-01 log names — "time strongly correlates with privileged
progress; predicting time must not be presented as predicting task progress" — and a
head reported at rho = +0.91 on all rows would be almost entirely a clock reader.
The latent does carry real non-clock signal: it predicts the residual after a
nonlinear clock fit at holdout rho = **+0.714**.

**Inside the stall basin, the clock is flat and the signal is genuinely
state-dependent.** At `t >= 260` the mean `Phi'` is 2.026 / 2.023 / 2.029 at
t = 400 / 550 / 700, and a variance decomposition gives:

- total basin `Phi'` variance `8.47e-4` (sd 0.0291);
- **within-timestep variance `7.83e-4` — 92.5% of it.**

So in the only region this round can affect, `Phi'` varies across episodes at the
same timestep, which is precisely the variation an advantage at a fixed horizon can
read.

**Fitting the head globally is systematically worse on the decision region — but
neither construction is well determined at 24 episodes.**

A first single-split measurement gave a globally-fitted head a decision-region holdout
rho of **−0.845** against **+0.510 / +0.708** for a region-fitted head. That single
figure does not survive replication and is withdrawn as a point estimate. Repeating
across five episode-disjoint splits (decision region = boundaries where the final goal

|---|---|---|
| 7 | −0.912 | +0.887 |
| 13 | −0.136 | +0.764 |
| 23 | −0.411 | −0.033 |
| 31 | −0.433 | +0.361 |
| 47 | +0.054 | −0.206 |

What this supports, and only this:

- the DIRECTION replicates — a globally-fitted head scores worse on the decision

### Two integration defects found and fixed after the implementation review

Both were invisible to the implementing agents because they were briefed before the
`Phi'` diagnostics above existed.

**1. The `Phi'` head was fitted over every boundary.** That is the construction
measured on 24 base episodes as the worse one — a nonlinear function of `t` alone
explains 97.2% of `Phi'` variance, so a globally-fitted head is largely a clock, and
over five episode-disjoint splits it scored worse than a region-fitted head on the
decision region in 5/5 (negative in 4/5). `scripts/train_v251_interface.py` now takes
`--phi-region-from-chunk`, fits the head on boundaries at or after that chunk index,
and **always reports both** the decision-region and the all-boundary held-out
correlation so the two can never be read as one another. The region one is the number
that gates the round. Four mechanical tests cover the restriction, the separated
metrics, arm-independence and an empty region.

**2. The trained interface would have been deployed ungated.** The D1 collectors and
the interface both see only boundaries at or after chunk 26, but
`run_v206_belief_residual_deploy.py` applied the residual at **every** chunk, with no
schedule flag at all. The interface would then have run for 26 chunks at states it was
never trained on — and the basin calibration measured precisely that regime as the one
that damages the first two sub-tasks, which the frozen policy otherwise completes in
24/24 episodes. Added `--residual-start-chunk` to the executor, asserted bit-exactly
(before the gate the executed chunk must equal the frozen policy's own), and wired it
through `scripts/eval_v251_round.py` so it reaches **every** arm including `base` —
applied identically, it cannot separate them. Three tests pin that it reaches all five
arms, that it is emitted even at 0 so a deployment cannot be silently ungated, and
that `base` still carries `--zero-residual` alongside it.

`162 passed`; `flake8 --max-line-length=100` clean.

Neither defect would have produced an error. The first would have returned a trained
interface driven by an advantage pointing the wrong way; the second would have
returned a deployment whose early damage was attributed to the world model. Both are
the failure shape this project keeps recording: a number instead of an exception.


### What the frozen policy is actually doing in the stall

Measured on the 24-episode base arm, comparing chunks 0-25 with chunks 26-74:

| | chunks 0-25 | chunks 26-74 |
|---|---|---|
| mean \|u\| (normalised action) | 0.5803 | 0.2940 (51%) |
| median EEF motion per chunk | 70.67 mm | 3.53 mm (5%) |

Per dimension, mean \|u\| early -> basin: x 0.441 -> 0.193, y 0.830 -> 0.262,
z 0.723 -> 0.284, rx 0.377 -> 0.046, ry 0.470 -> 0.118, rz 0.230 -> 0.208,
**gripper 0.990 -> 0.949**.

The policy is **not idle in the stall — it is dithering**. It keeps issuing commands at
half its normal magnitude, with the gripper channel still saturated, and they produce
5% of the normal net motion. Translation commands collapse and rotation commands
nearly vanish, which is the signature of small conflicting corrections cancelling out
rather than of a paused controller.

This reframes the 0.80 residual precisely. Its mean \|delta\| = 0.440 is compared
against the base magnitude **in the region where it is applied**, 0.294 — so it is
about 1.5x the command it is added to, and it dominates. But what it dominates is a
command that nets 3.5 mm of motion per chunk. The honest description of the
intervention is *a coherent sustained bias supplied during a region where the frozen
policy's own commands cancel*, not *a small correction to a working controller*.

**A mechanistic hypothesis this suggests, recorded as a hypothesis.** If the residual
has to exceed the dithering magnitude to produce net motion, the useful threshold
should sit near \|delta\| ~ 0.29. The ladder is consistent with that: \|delta\| =
0.051, 0.105 and 0.206 are all below it and none moved the outcome, while 0.440 is
above it and moved every reach and outcome column. This is an account consistent with
five points, not an established mechanism; the arms now running (1.60, and two further
inits at 0.80) test whether the ladder keeps rising above the threshold or flattens,
which is the difference between "a coherent bias breaks the dither" and "a large enough
arbitrary perturbation eventually knocks the box in".

5 cm grasp radius, picking the third object up in 4/24 and producing 1/24 terminal
success, against 0/24 for frozen pi0.5 on the same seeds. Without this arm, a trained
interface that merely MATCHES an untrained one at the same magnitude would be reported
as an improvement over base, and the trust region's own effect would be credited to
the world model. The registered arms are now:

| arm | what it isolates |
|---|---|
| `base` | frozen pi0.5, `Delta := 0`, identical code path |
| `rand` | untrained random residual at the round's scale |
| `M0` | stale WM, transition trained on D0 only |
| `M1` | updated WM, transition trained on D0 + D1 |
| `M1_shuf` | updated WM with the D1 action pairing broken |
| `Q` | same data, same rows, same head, no latent ever rolled forward |

Primary contrasts: `M1 vs M0`, `M1 vs Q`, `M1 vs rand`, `M1 vs M1_shuf`, `M1 vs base`.
Context contrasts: `M0 vs base`, `Q vs base`, `rand vs base`, `M0 vs Q`, `M0 vs rand`.

The cost is paid deliberately: the Holm family grows from 3 primary tests to 5, so
every individual contrast now has to clear a stricter bar. Dropping controls to keep
significance reachable is the failure this project records, so the controls stay and
the bar rises. Budget becomes 6 arms x 288 = 1,728 evaluation episodes, ~10.6 h.

**2. The "no damage" half of the D1 scale criterion is withdrawn as vacuous.**
Milestones 0-3 are produced by chunks < 26, which the schedule gate leaves unperturbed
by construction, so "24/24 intact" holds at every scale and carries no information.
The criterion is now outcome-relevant consequence variation — reach distance spread and
milestone-4 events — with the ladder's shape used to distinguish "a coherent bias
breaks the dither" from "a large enough arbitrary perturbation eventually knocks the
box in". The scale is fixed only after the 1.60 and replicate arms report.

**3. The deployment schedule gate is registered.** `--residual-start-chunk` is passed
identically to all six arms, including `base`, and must equal the value the D1
collectors and the interface were trained under. Applied identically, it cannot
separate the arms; omitted, it would run the interface for 26 chunks at states it
never saw.


### The ladder extended to 1.60 — an interior optimum, not a monotone one

| arm | scale | \|delta\| | d_min median | <0.05 m | <0.30 m | m4 | m5 | success | paired closer/farther |
|---|---|---|---|---|---|---|---|---|---|
| base | — | 0 | 0.5022 | 0/24 | 4/24 | 0 | 0 | 0 | — |
| resid | 0.10 | 0.051 | 0.4813 | 1/24 | 4/24 | 0 | 0 | 0 | 12 / 10 |
| resid | 0.20 | 0.105 | 0.4807 | 1/24 | 7/24 | 0 | 0 | 0 | 11 / 10 |
| resid | 0.40 | 0.206 | 0.4728 | 0/23 | 4/23 | 0 | 0 | 0 | 14 / 7 |
| **resid** | **0.80** | **0.440** | 0.2690 | **7/24** | 13/24 | **4** | **1** | **1** | 15 / 9 |
| resid | 1.60 | 0.975 | **0.2431** | 3/24 | **17/24** | 2 | 0 | 0 | **20 / 4** |

**The two columns move apart, and that is the finding.** Approach improves
monotonically with scale — 1.60 has the best median closest approach (0.243 m), the
most episodes inside 0.30 m (17/24) and by far the strongest paired effect (20 closer,
4 farther). But grasp conversion peaks at 0.80 and falls: 1.60 picks the object up in
2/24 against 4/24, places it 0 times against 1, and succeeds 0 times against 1.

A residual large enough to drive the arm at the object reliably is too large to close
on it.

**What this rules out.** The deflationary reading of the 0.80 result was that a large
enough arbitrary perturbation eventually knocks the box in. If that were the mechanism,
1.60 would dominate 0.80 on every column, since it is twice the magnitude and does
reach the object more often. It does not. There is an **interior optimum in the
outcome metrics**, which means the useful intervention is a particular one rather than
simply a big one — and a state-dependent choice among interventions is exactly what a
world model could supply and an untrained residual cannot. The round's premise
survives the test that was designed to break it.

It also splits the dithering account into two separate constraints: a lower threshold
near \|delta\| ~ 0.29 governing whether the arm moves at all (0.051 / 0.105 / 0.206
produced nothing; 0.440 / 0.975 produced approach), and an upper ceiling governing
whether motion converts into a grasp.

Still n = 24 per arm and still counts rather than tests. Two further inits at 0.80 are
running to separate the scale from the particular random actor before D1 is fixed.


### `scripts/build_v252_rand_actor.py` — the untrained control arm

The `rand` arm needs a deployable checkpoint, and getting it wrong would quietly
break the control. Four properties make it *matched* rather than merely random:

- same architecture (`ResidualActor`, bounded by `scale * tanh`);
- **same coordinates** — `mu`/`sd` come from the model pair the trained arms use, not
  from the collector's `d0_latent_stats.pt`. A random actor conditioned on different
  normalisation is a different function of the observation, and the contrast would
  confound the interface with its input space, which is the v235 error;
- same calibrated init gain (10.0), so the measured `|delta| ~ 0.536 * scale` carries over;
- same executor, panel and `--residual-start-chunk` schedule.

`ResidualActor` zero-initialises its output layer, so an untouched instance is
identically a no-op and would silently duplicate `base`. The first test asserts exactly
that failure is not what ships. Six CPU tests: not-a-no-op, respects its own bound at
0.1/0.8/1.6 far outside the data range, reproducible with inits separating actors,
state-conditioned rather than a constant bias, the gain constant has not drifted from
the collectors, and the output is chunk-shaped. `6 passed`.

The embedded `rawwm` exists only so the executor can construct its belief module; under
`condition="raw"` the actor reads the normalised latent alone and the belief output is
discarded. Recorded in the provenance so it is not mistaken for a model this arm consults.


### Pre-registration correction: the primary endpoint

The pre-registration above named **basin-minimum EEF-to-active-object distance** as the
primary powered endpoint, with milestone-4 as the primary binary one. The
implementation had milestone-4 as primary and no distance endpoint at all. Reconciling
them, the implementation is right and the pre-registration was wrong, for a reason the
calibration measured after that text was written:

**On the ladder, distance moves OPPOSITE to the outcome.** Scale 1.60 has the best
closest approach of any arm — median 0.243 m, 17/24 episodes within 0.30 m, 20/24 seeds
closer than base — while picking the object up in 2/24 against 0.80's 4/24, placing it
0 times against 1, and succeeding 0 times against 1. A round with distance as its
primary endpoint could therefore be WON by an arm that drives the gripper at the object
and never closes on it, and the headline would be an improvement that is not one.

So:

- **primary: milestone-4 attainment** (`pick_up cream_cheese_1`), paired McNemar with
  the full discordant table;
- **estimation only: terminal success**, Clopper-Pearson, never a verdict;
- **secondary: `d_min_final_atom`**, newly added, carrying that warning in its own
  registration text so it cannot be read as the outcome later.

`d_min_final_atom` is computed in the deploy executor
(`run_v206_belief_residual_deploy.final_atom_reach`) over boundaries where the FINAL
goal atom is the active one, and is read straight through by the driver rather than
reconstructed from a distance series — an unrestricted minimum is a different quantity
that reads 9/24 within 5 cm where the restricted one reads 0/24. Five tests pin the
restriction: a can during its own placement is not counted, a completed final atom is
not active, the basin gate excludes earlier boundaries, the minimum is over qualifying
boundaries only, and no qualifying boundary reports `None` rather than a number.

Secondary family grows from 3 x 5 = 15 to 4 x 5 = 20 Holm-corrected tests.

`173 passed`; flake8 clean.


### `--phi-readout head`, not the default

`train_v251_interface.py` defaults to `--phi-readout label`: the `observed` and
`current` controls read `Phi'` straight off the supplied annotation, while `predicted`
has no annotation at an imagined latent and must read it through the learned head.

Under that default the `M1 vs Q` contrast would differ by **two** things — predicted
versus real future, AND a learned head versus the exact annotation — and only the first
is what the contrast claims to isolate. Q would be handed a cleaner signal than M1,
which biases the comparison against the world model and would make a null
uninterpretable rather than informative.

The round therefore runs every arm with `--phi-readout head`, so all three advantage
modes read `Phi'` through the identical frozen head and the rollout is the only
remaining difference. Recorded here because it is a deliberate departure from the
script's default.


### `scripts/gate_v251_prelaunch.py` — automated go/no-go before the 10.6 h evaluation

The evaluation is 6 arms x 288 episodes. Three upstream failures would make every one
of those episodes uninterpretable, and all three are visible for free in artifacts that
already exist by then:

1. **The actor collapsed to a no-op.** `ResidualActor` zero-initialises its output
   layer, so an interface that learned nothing IS the `base` arm exactly. Four arms
   would be four copies of the control, every contrast a null by construction, and the
   null would be reported as a null about world models. Gate: mean\|delta\| must exceed
   1% of its own bound on every restart.
2. **The `Phi'` head has no signal where it is used.** Gate: the head must be
   `region_restricted` and its DECISION-REGION held-out correlation must exceed 0.10.
   The bar is deliberately low — the 24-episode measurement put a region-fitted head
   anywhere in [-0.21, +0.89] across five splits, so a high bar here would be fitted to
   noise. It only excludes a head carrying no signal at all where it is read.
3. **The arms are not matched.** Gate: one shared `Phi'` head digest, one shared
   normaliser digest, and identical (epochs, batch, restarts, horizon, scale) across
   arms. Plus: the `rand` arm must be marked untrained and must not be identically zero.

Exercised against five synthetic failures, each caught with the right message:
collapsed actor, differing head digests, a globally-fitted head, a dead head
(corr 0.01), and a mismatched optimiser budget. A clean set returns GO.

**The gate does not predict or require a positive result and reads no outcome.**
Passing it means the comparison is well posed, not that the world model helps. A round
that passes and then shows nothing is a completed experiment.

`collection -> model pair -> 4 interface arms + rand -> GATE -> dry-run
(preregistration + power, no simulator) -> 6 arms x 288 evaluation`, each stage
refusing to start unless the previous one printed its completion marker.

### Finding 1 (critical): `M1 vs M0` was also a compute contrast

`build_v241_model_pair` trains `stale` for `--base-steps` (4000) and builds `updated`
as `deepcopy(stale)` plus a further `--update-steps` (3000). **M1 therefore had 7,000
optimiser steps against M0's 4,000 — 75% more — on top of seeing D1.** The
pre-registration's "M1 and M0 differ only in the learned transition" was false as built,
and the headline contrast would have confounded updated dynamics with extra gradient.

`base_continue` is the arm that fixes it — M1's total budget on D0-only data — and it
already existed in the pair and was simply never deployed. Repair: it is deployed as
**`M0_cont`**, the primary dynamics contrast becomes **`M1 vs M0_cont`**, and `M1 vs M0`
drops to context. Seven arms, 288 seeds each.

### Finding 2 (critical): the realised intervention magnitude was never compared

Every arm records `mean_abs_delta` per episode and nothing read it. `scale` pins the
BOUND, not the intervention: two arms can share a bound, share every flag, and still
execute different-sized residuals — and the calibration ladder attributes every
endpoint to magnitude (\|delta\| 0.051/0.105/0.206 produce zero milestone-4 events,
0.440 produces 4/24). An unreported difference here would have been read as an effect
of the transition. Repair: the executor now writes `mean_abs_delta_panel`, the driver
reports it per arm, and a hard check fires when treated arms deviate from the panel
mean by more than a pre-registered 25%.

### Finding 3 (critical): two of five primary contrasts were never matched-checked

`check_matched` and `check_run_matched` compared only `("M1", "M0", "Q")`, so `rand`
and `M1_shuf` — both primary contrasts — were fingerprinted and then discarded. Repair:
both checks now iterate `ARM_ORDER` minus `base`.

### Finding 4 (high): `MATCHED_FIELDS` compared fields nothing writes

`epochs` and `beta` are written by no script, so those comparisons passed by matching
`None` to `None`, while `phi_head_digest` and `model_pair_sha256` — the fields that
actually carry the round's "one shared head, one shared pair" guarantee — were absent.
Repair: dead fields dropped, real ones added, with the head digest and pair hash
treated as structural.

### Also repaired: four dangerous defaults

The audit noted that no runner script exists in the repository, so an operator types
these commands from the docstring — and the docstring examples disagreed with the
pre-registration. `--horizon` defaulted to 5 against a committed H=10; `--phi-readout`
defaulted to `label`, which breaks the `M1 vs Q` isolation; `--phi-region-from-chunk`
defaulted to `None`, the construction measured as anti-correlated on the decision
region; and `--scale` defaulted to 0.05, one ninth of the calibrated magnitude and
below the threshold for any measured effect. `--scale` is now REQUIRED with no default,
the other defaults are the registered values, and the docstring examples are corrected.

`173 passed`; flake8 clean.


### The fixed horizon was not fixed — found by audit, confirmed from the calibration data

**The defect.** `ChainEnv.step` splits robosuite's `done` and `check_success()` into
`info`, and this log recorded that keying the collector loop off `info["done"]` instead
of `terminated` gave a fixed horizon. It does not: **`info["done"]` is itself
success-driven on this task.**

Confirmed from calibration artifacts already on disk:

| run | seed | success at | episode ran | full-horizon |
|---|---|---|---|---|
| `cal_r0.80` | 9018 | step 678 | **678 steps** | 23/24 |
| `cal_r0.80i2` | 9010 | step 721 | **721 steps** | 23/24 |

Every successful episode was truncated at exactly its success step. Row count still
predicted the outcome perfectly — the precise leak the fixed horizon exists to remove,
in a collector this file described as having removed it.

**Why my verification missed it.** The smoke test was run on seed 8704, chosen because
that episode was success-censored in the historical D0. Under this collector's own
sigma draw seed 8704 does NOT succeed, so the test never exercised the success path at
all. A fix verified on a case that cannot trigger it is not verified.

**The repair, and the measurement that licenses it.** A direct probe on seed 9018 with
the success path deliberately ignored: `info["done"]` first fires at t=678, the same
step as `is_success`; stepping past it raises nothing, reaches t=750/750 and 75/75
chunks, and leaves `predicate_bits` readable (`[True, True, True]`) with the milestone
record intact (`{0:70, 1:140, 2:220, 3:270, 4:580, 5:680}`). So under a fixed horizon
only a `done` that is NOT a success, or a truncation, may end the episode. Applied to
both `collect_v250_chain3_round.py` and `run_v206_belief_residual_deploy.py`.

End-to-end check on the failing case: seed 9018 now yields **t=750, 75 rows, all six
milestones, success recorded, 1/1 full-horizon**. Five regression tests pin the
predicate itself — success-driven done does not stop, a genuine failure terminal does,
truncation does, and the non-fixed-horizon path is unchanged.

**Consequence for the round.** The collection launched before this was found was killed
and its partial D0 and D1 discarded; nothing from it survives. The calibration arms
retain the leak in their two successful episodes out of 192, which is declared: their
milestone and reach counts are unaffected (those are read from the automaton, not from
row counts), but their tapes are not used for training anything.


### Remaining audit repairs, before relaunch

**`APPROACH_REFERENCE` was clipping hardest exactly where it mattered.** Measured over
all 192 calibration episodes the largest EEF-to-active-object distance is **1.186 m**,
and at residual scale 0.80 — the D1 setting — **23.6% of boundaries exceeded the 0.60 m
reference and clipped to exactly zero**. Per-arm clipped fractions were base .027 /
0.10 .027 / 0.20 .064 / 0.40 .038 / **0.80 .236** / 0.80i1 .067 / 0.80i2 .056 /
1.60 .095. That is the A1 saturation reintroduced through a different constant, and
concentrated in the episodes where the residual is doing something. Raised to 1.25 m:
zero clipping, and the scale-0.80 basin `Phi'` now has sd 0.154, range 1.220 and 1,058
distinct values over 1,193 boundaries. It costs dynamic range (the useful 0.50 -> 0.05 m
span maps to 0.072 rather than 0.150), which is the right trade because AWR standardises
its advantage and needs monotonicity, which clipping destroys, far more than scale.

**`phi_basin_mean` was a registered endpoint nothing computed.** The driver can only
read it through or rebuild it from a per-boundary series with its `t`, and the executor
wrote neither — so after a full 12 h evaluation it would have come back `unavailable`.
Now computed per episode in the executor, restricted to final-atom-active boundaries
for the same reason `d_min` is: `Phi' = completed + phi(active)`, so a mean over
boundaries with different active atoms is dominated by the integer term and mostly
measures WHEN the second object was placed.

**`Endpoint.direction` was registered and never applied.** `d_min_final_atom` carries
`direction = -1` (closer is better). Unapplied, an arm that approached the object more
closely would have printed as *worse*, with its bootstrap interval sign-flipped.
Differences are now oriented so "better" means better for every endpoint, with
`raw_mean_difference` keeping the unoriented value visible. Two tests pin both signs.

**The interface bound is now checked against the trust region its targets came from.**
`train_v251_interface.py` reads `actor_scale` and `residual_start_chunk` out of each D1
run's `manifest.json` and refuses a `--scale` or `--phi-region-from-chunk` that
disagrees, or a set of runs collected at different scales. Regressing a scale-0.05
actor onto scale-0.80 deltas asks it to represent targets 16x outside its range; the
calibration says such an interface cannot move the task at all, and the round would
have reported "training destroys the effect" with nothing flagged. Four tests cover it.

`184 passed`; flake8 clean; every entry point's `--help` parses (one help string
contained a literal `%`, which crashed argparse's formatter on any usage error).


### Correction to a claim made twice in this file

This file states, of `Phi'`, "It is identical across every arm, so it cannot explain a
between-arm difference." That is **false as written** and the audit was right to flag
it. `Phi'` is identical across the five arms that are TRAINED on it — `M1`, `M0`,

- `M1 vs rand`, `M1 vs base` — these compare a policy trained on a privileged progress

  annotation plus the training pipeline helps, NOT that the world model does, and it
  must not be reported as the latter.

## 09-12 gate GO, and how different the arms actually are

### Gate: GO

All five trained arms share one `Phi'` head (identical digest, decision-region
held-out correlation **0.389**, all-boundary **0.844** — the gap between those two is
the clock effect this round was built around). Residual magnitudes 51.7–54.0% of bound
on every restart, so no arm collapsed to a no-op. Budgets matched. `rand` untrained
with a non-zero probe.

### The arms are distinct, and by how much is a pre-run bound on the result

Measured on 600 real basin latents in the model pair's coordinates, before any
evaluation:

| pair | mean \|dA − dB\| | relative | cosine |
|---|---|---|---|
| M1 vs M0_cont | 0.1091 | 0.263 | +0.936 |
| M1 vs M0 | 0.1088 | 0.264 | +0.935 |
| M1 vs M1_shuf | 0.1139 | 0.276 | +0.930 |
| M1 vs Q | 0.1300 | 0.322 | +0.915 |
| any trained vs **rand** | ~0.58 | ~1.32 | **−0.03** |

Two things follow, and both belong in the report regardless of outcome.

1. **Training produces something orthogonal to random.** Every trained arm has
   cosine ≈ 0 with the untrained residual while sharing its magnitude (0.39–0.46 vs

2. **The four world-model variants are variations on ONE function, differing by

   thing that differs between M1, M0, M0_cont and M1_shuf — modulates the output by
   about a quarter. Whether a 26% change in residual direction converts into an outcome
   difference at n=288 is exactly what the round measures. If the result is null, this
   number is the first explanation to reach for, and it was recorded before the run.

### A repair the first launch forced

Widening the matching checks to cover `rand` (an audit finding) aborted the real run:
`rand` is UNTRAINED by construction and therefore carries no `phi_readout`,
