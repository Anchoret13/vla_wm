## Decision

The active method is

\[
\text{VLA proposal bank}
\xrightarrow{\text{frozen LCWM/outcome score}}
\text{prior-aware hard selection or abstention}
\xrightarrow{\text{flow post-training}}
\text{recurrent full-prompt }N=1\text{ policy}.
\]

The scorer is first tested as a **prospective intervention**, not by enlarging
the old seven-pair ranking table. Every new anchor is selected before candidate
scoring; the LC selection and matched control are frozen before any candidate
outcome is observed; and the complete candidate bank is then executed. The
same rollout therefore provides:

1. a direct test of whether the frozen LC scorer chooses a better action than
   stock and a matched random identity;
2. proposal headroom, oracle regret, null-state safety, and the decisive
   predicted outcome component;
3. new winner, loser, tie, null, and regression transitions for the single
   allowed replay refresh if the selector fails; and
4. a frozen teacher ledger for hard `N=1` distillation if it succeeds.

MPAIL contributes the policy-prior interpretation; MPAIL2 contributes the
accumulated off-policy replay loop. Neither deployment-time MPPI nor a new
planner is introduced. Final deployment remains recurrent full-prompt `N=1`
pi0.5 with no external scorer.

## V7.1.4A — Compile the frozen selector without creating a new gate

This is a correctness repair required to execute V7.1.4B. It is not a separate
ranking study.

For candidate `i`, stock candidate `0`, supported outcome component `d`, and
ensemble member `k`, compute a paired difference

\[
\Delta_{i,d}^{(k)}
=
\hat y_d^{(k)}(z,u_i)-\hat y_d^{(k)}(z,u_0),
\]

then

\[
L_{i,d}=\operatorname{Mean}_k\Delta_{i,d}^{(k)}
-\operatorname{Std}_k\Delta_{i,d}^{(k)},
\qquad
U_{i,d}=\operatorname{Mean}_k\Delta_{i,d}^{(k)}
+\operatorname{Std}_k\Delta_{i,d}^{(k)}.
\]

Use the same ensemble index on the candidate and stock sides. Do not subtract
the marginal standard deviations of two independently assembled absolute
outcomes. With `K=5`, `[L,U]` is a frozen ensemble margin band / LCB heuristic,
not a calibrated statistical confidence interval. The words
`confidence-positive` below name the registered decision rule, not a coverage
claim.

### Frozen selector rule

- [ ] Mask `success_by_100` and `neg_damage` from predicted selection in the
  first run because their training targets are constant. Continue to measure
  real success and damage as hard behavior/safety outcomes.
- [ ] Use the supported registered component order
  `p_valid_100 -> q_valid_mean -> neg_tau_next`, with the already frozen
  replay-noise tolerances. Save `q@10/30/60/100` as diagnostic predictions;
  do not silently insert them into the first selector or call them a separately
  validated Tail-Q.
- [ ] Before comparison, project predictions to their registered target
  domains: `p_valid_100,q_valid_mean,q@h in [0,1]` and normalized
  `neg_tau_next in [-1.01,0]`. Record both raw and projected values; an
  unconstrained output outside the target domain cannot create artificial
  lexicographic headroom.
- [ ] For each candidate-versus-stock comparison, apply a ternary
  lexicographic confidence rule at every component:
  - `L > +tol`: confidence-positive and decisive;
  - `U < -tol`: confidence-negative and ineligible;
  - `[L,U]` contained within `[-tol,+tol]`: supported tie, continue to the
    next component;
  - otherwise: uncertainty crosses a decision boundary, so that candidate is
    ineligible.
- [ ] If every component is a supported tie, the candidate is tied and
  ineligible. If no candidate is confidence-positive, abstain and execute
  `u_0`.
- [ ] Among confidence-positive candidates, select the lexicographic maximum
  ensemble-mean supported outcome. Break an exact tolerance-level tie by the
  frozen SHA256 of `(run_id, source_id, decision, candidate_id)`.
- [ ] Emit one pre-outcome ledger row per anchor containing every component
  mean/std, paired interval, eligibility result, decisive component, selected
  family/candidate, abstention reason, and tensor/checkpoint hashes.
- [ ] Add a mechanical assertion that a masked head cannot be decisive and
  that the selector ledger is byte-frozen before the first candidate branch is
  executed.

Do not rerun or expand the old V7.1.3 ranking set as a launch condition. A
single tensor-only replay of the existing rows is allowed only to verify that
the compiled selector obeys these assertions; it is recorded as a unit test,
not new scientific evidence.

## V7.1.4B — Prospective frozen-selector intervention

This is today's primary method experiment.

### Source and anchor binding

- [ ] Use one fresh train-side stock source per public-LoHo task with seeds
  `2300 + 10*k`, `k in {0,1,2,3,4}`. These sources are disjoint from all
  prior 2000/2100/2200 families.
- [ ] Reserve `2301 + 10*k` without inspecting it. It is the next fresh
  evaluation source family: held-out `N=1` policy evaluation if the selector
  passes, or the one final post-refresh selector evaluation if it fails.
- [ ] Reuse the V7.1.1 state-diverse anchor rule over all registered subgoals:
  stall, recovery, late-chain, and milestone-boundary priority; at most four
  anchors per source; at least five policy decisions apart; never select by
  elapsed-time percentile.
- [ ] Freeze every anchor from the stock trajectory using only pre-action
  state/history and GoalSpec automaton state. Candidate scores and candidate
  outcomes are unavailable when the anchor list is fixed.
- [ ] Complete the frozen source/anchor budget even if the first tasks show no
  intervention or no headroom.

### Candidate bank and proposal claim boundary

At every anchor generate:

```text
u_0             deployed canonical full-prompt stock chunk
u_canon[1..7]   seven additional canonical full-prompt pi0.5 samples
u_atomic[0..1]  two provenance-labeled atomic-prompt VLA samples
u_distinct[0..1] two compatible distinct-goal VLA samples
u_0_repeat      exact first-ten action replay audit; not a candidate
```

- [ ] Exclude servo, scripted actions, replay branches, and privileged-state
  controls from the policy-eligible pool.
- [ ] Freeze proposal/action-noise seeds by
  `SHA256("v071_selector_r1|proposal|source|decision|family|index")`.
  Generate every proposal before observing any candidate outcome.
- [ ] The primary method uses the full proposal-augmented VLA pool. Report a
  nested canonical-only selector using the already executed
  `{u_0,u_canon}` subset; never choose which pool is primary after seeing
  outcomes.
- [ ] Generate `u_0` and all seven `u_canon` actions under the identical full
  prompt with independent registered flow-noise seeds; these eight samples are
  the exchangeable canonical pool. Freeze the exact atomic/distinct prompts,
  GoalSpec fields used to construct them, and their seed-to-index mapping.
- [ ] Describe only the nested canonical pool as an empirical pi0.5-prior
  update. Atomic/distinct candidates form an explicitly registered proposal
  mixture, not exchangeable samples from the canonical prior. If their prompts
  use the known `first_unresolved` subgoal or another GoalSpec field, label the
  result training-time oracle proposal augmentation; an expanded-pool win is
  not attributable to LCWM alone.

### Matched selection control

- [ ] Freeze the LC-selected candidate or abstention before outcome execution.
- [ ] Build one matched-permutation selector with exactly the same nonstock
  intervention mask and selected-family mass as LC selection.
- [ ] On an LC intervention, choose a different candidate from the same family
  by a frozen hash-cyclic permutation; fixed points are forbidden. On an LC
  abstention, the control also keeps `u_0`.
- [ ] The matched control therefore changes only candidate identity within the
  family. It cannot change intervention rate, anchor set, proposal support,
  continuation budget, or selected-family distribution.
- [ ] Treat one pre-registered derangement as the promotion control. Because
  the complete bank is executed, also report the counterfactual distribution
  over 32 independently hash-seeded within-family derangements at zero extra
  simulator cost. These secondary controls cannot replace or reselect the
  designated gate control.

The permutation comparison tests whether LC chose the right candidate identity
after its own intervention and family decision. It does not control the
abstention or family-selection decision; the end-to-end primary comparison is
LC selection versus stock over all frozen anchors.

### Execute the complete bank

- [ ] From one verified in-memory snapshot per anchor, execute the first ten
  actions of all 12 policy candidates plus the exact `u_0_repeat` audit.
- [ ] Verify the same anchor proprio/object/semantic checksums before every
  branch and hash-randomize branch execution order. The order seed is frozen in
  the manifest and unavailable to the selector.
- [ ] For all policy candidates run `R=2` stock pi0.5 continuations with
  sibling CRNs
  `SHA256("v071_selector_r1|cont|source|decision|goal|repeat|cont_decision")`.
  Candidate, selector, and control identity must be structurally absent from
  the continuation seed.
- [ ] Evaluate the GoalSpec after every environment action and store raw
  external/wrist observations, proprioception, environment/normalized
  actions, semantic states, success, damage, ordered progress, milestone time,
  and all multi-horizon continuation outcomes.
- [ ] Retain and append every winner, loser, tie, null, regression, and
  fidelity row to an immutable prospective replay tranche. Do not retain only
  selected or oracle-positive branches.
- [ ] Compute real outcomes only after the selector and matched-control ledgers
  are sealed. Never regenerate selection after seeing which branch worked.
- [ ] Apply the registered both-repeats-agree rule: conflicting `R=2`
  continuation preferences are `unstable/tie`, never resolved by majority,
  best-repeat selection, or a third post-hoc rollout.

### Synchronous diagnostic readouts

The following are outputs of the intervention, not prerequisites for it:

- [ ] decisive predicted component and frozen ensemble margin band for every

- [ ] intervention/abstention rate by task, source, anchor type, and proposal
  family;
- [ ] complete-bank oracle headroom, LC oracle regret, and canonical-only
  versus expanded-pool headroom;
- [ ] false intervention and outcome regression on true null/no-headroom

- [ ] real success/damage changes, replay fidelity, and source-level paired
  margins;
- [ ] `q@10/30/60/100` prediction error/ranking as an auxiliary report only.

No history attribution, new representation probe, or scorer architecture
comparison is added to this run.

### Prospective hard-selector gate

Use the registered both-repeat lexicographic ground-truth preference. Repeats
and candidates from one anchor are not independent samples. Aggregate with
equal task, then source, then anchor mass.

The frozen selector teacher passes only if:

- [ ] LC selection has positive all-anchor aggregate paired margin versus
  stock, including abstentions, false interventions, and null anchors;
- [ ] LC selection has positive aggregate paired margin versus the designated
  matched-permutation selector over intervention anchors;
- [ ] at least two independent sources have a positive LC-versus-stock
  direction, rather than multiple candidates/repeats from one source;
- [ ] the true null/no-headroom-anchor LC-versus-stock margin is nonnegative;
- [ ] there is no success loss or new damage relative to stock.

Report intervals and all source-level directions, but do not invent a

sources with either oracle headroom or LC interventions is `coverage
insufficient`, not a selector win. Non-safety source regressions are allowed

be shown individually and cannot be averaged away in the narrative. Oracle-

## V7.1.4C — Hard-teacher flow distillation

Launch immediately after the prospective selector passes. Do not enlarge the
offline ranking benchmark first.

### Frozen teacher data

- [ ] Use the pre-outcome selector ledger exactly as frozen. Real outcomes may
  evaluate the teacher but cannot delete its mistakes, replace its choices by
  oracle winners, or turn abstentions into corrections.
- [ ] Each anchor contributes at most one confidence-positive nonstock
  correction target. Equalize mass by task, source, and anchor; candidate-rich
  anchors cannot receive more optimization weight.
- [ ] Abstention, true-null, and tied anchors receive state-local stock-flow
  trust and demonstration rehearsal but no arbitrary one-sample `u_0`
  correction target.
- [ ] Give correction credit only to the executed first ten actions. Preserve
  the registered branch-independent suffix/trust contract for the unexecuted
  forty actions.

### Frozen policy boundary and arms

Use the V7.1.0B boundary with identical stock pi0.5 initialization and
zero-initialized LC projection for every trained arm. The trainable parameter
names, optimizer, step budget, balanced anchor schedule, rehearsal schedule,
flow noise/time, trust coefficients, checkpoint cadence, and final-step rule
must be bound before training and byte-matched across arms. No hyperparameter
sweep is allowed.

| arm | correction signal | deployment |
|---|---|---|
| stock | none; frozen pi0.5 | recurrent full-prompt `N=1` |
| BC-only PEFT | stock `u_0` target at the same intervention anchors + demonstration BC/trust | recurrent full-prompt `N=1` |
| LC-hard PEFT | one frozen LC-selected target at each intervention anchor | recurrent full-prompt `N=1` |
| permutation-hard PEFT | same intervention anchors, matched-family permuted target | anchor gate only |

- [ ] Do not call uniform imitation of every candidate `BC-only`; that is a
  multimodal target mixture and is not the behavior-policy baseline.
- [ ] Apply the BC-only anchor target only where the frozen LC ledger
  intervenes, using the corresponding pre-outcome `u_0`. On LC abstention
  anchors, both BC-only and LC-hard receive only the matched trust/rehearsal
  terms. This matches correction states and update mass without turning null
  anchors into one-sample stock corrections.
- [ ] Train correction, demo rehearsal, and stock trust under recurrent LC
  state consistently. Reset is not a separately optimized policy.
- [ ] Emit every final checkpoint even if offline reconstruction is poor.
  Offline flow loss cannot select or terminate an arm.
- [ ] Save first-ten target reproduction, matched-noise action shift, stock
  retention, and reset/shuffle state readouts as diagnostics attached to the
  policy run. They do not replace behavior execution.

### Fresh `N=1` behavior gate

If V7.1.4B passes on the `2300 + 10*k` sources, use the pre-reserved
`2301 + 10*k` source family for the first source-held-out student comparison.
Freeze its anchors from stock trajectories before running any learned arm.

- [ ] Execute stock, BC-only, LC-hard, and permutation-hard from the same
  verified anchor snapshots with shared action-generation noise and `R=2`
  sibling stock continuations.
- [ ] Require LC-hard to beat stock and BC-only on the equal-task/source/anchor
  paired outcome, and to beat permutation-hard on intervention-capable
  anchors.
- [ ] Require positive direction on at least two independent sources, no
  success loss or damage increase, and no negative aggregate margin on null
  anchors.
- [ ] Distinguish train-anchor target transmission from fresh-source policy
  generalization. A train-only win is not a policy promotion.
- [ ] Only a fresh-source `N=1` win opens one public-LoHo development matrix.

Soft MPAIL-style weights are deferred. If the hard student improves positive
anchors but produces a null-state regression, one prior-preserving soft arm may
be trained from the same stock initialization under a separately frozen
temperature/ESS contract. It may not continue from the hard checkpoint or
trigger a beta sweep.

## Pre-registered failure routing

The prospective run must end in a method intervention or reusable replay, not
only a diagnosis report.

| Observed result | Next action |
|---|---|
| Full VLA pool has headroom, but LC is approximately matched permutation or abstains everywhere | Append the complete bank to the union; refresh the same outcome/Q ensemble once with the same architecture and frozen LCWM; use reserved `2301 + 10*k` sources for one final prospective selector test |
| Full VLA pool itself has insufficient headroom | Keep the scorer fixed; run one bounded proposal-support expansion using more canonical batches, shifted previous-chunk suffix/warm-start proposals, and atomic/distinct VLA proposals |
| LC selector passes prospectively | Freeze its pre-outcome ledger and launch V7.1.4C hard distillation immediately |
| Direct LC teacher works, but the hard student cannot reproduce it on train anchors | Use the new selected/sibling replay for one bounded redistillation under the same boundary; no representation or adapter sweep |
| Hard student fits train anchors but fails the reserved fresh sources | Record a coverage/generalization failure; use the single accumulated-replay refresh, then one final student run |
| Hard student improves but regresses on null states | From stock initialization, run one registered soft prior-preserving arm; no beta sweep |
| Hard or registered soft `N=1` beats stock and BC-only on fresh sources | Freeze one checkpoint and run one `5 tasks x 5 seeds` public-LoHo development matrix |
| The fixed replay refresh still leaves the prospective selector or student below its matched controls | End the current policy-improvement route with a bounded negative result; do not open a feature/EMA/LoRA/coupling sweep |

If the first selector fails and consumes `2301 + 10*k` as its post-refresh
evaluation family, reserve `2302 + 10*k` for the eventual fresh `N=1` student
gate. A source family is used for only one routing decision.

The single scorer refresh is defined now: keep `lc_full_selected.pt` frozen;
rebuild the expanded replay union; and train the same `K=5`, 768-256-256-9
outcome ensemble **from scratch** with the same heads, target transforms,
sampler, member seeds, optimizer, epoch budget, tolerances, margin multiplier,
and abstention rule. Only the replay rows change. Refreshing LCWM, adding a new
Q network, changing selector thresholds, or warm-starting a selected scorer is
outside this route. A later policy-only redistillation is a separate bounded
interface action and cannot be used to authorize a second scorer refresh.
