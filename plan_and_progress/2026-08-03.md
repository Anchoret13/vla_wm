## Decision

The active method is

\[
\text{VLA proposal bank}
\xrightarrow{\text{frozen LCWM/outcome score}}
\text{prior-aware hard selection or abstention}
\xrightarrow{\text{flow post-training}}
\text{recurrent full-prompt }N=1\text{ policy}.
\]

The scorer is first tested as a **prospective intervention**, not by enlarging
the old seven-pair ranking table. Every new anchor is selected before candidate
scoring; the LC selection and matched control are frozen before any candidate
outcome is observed; and the complete candidate bank is then executed. The
same rollout therefore provides:

1. a direct test of whether the frozen LC scorer chooses a better action than
   stock and a matched random identity;
2. proposal headroom, oracle regret, null-state safety, and the decisive
   predicted outcome component;
3. new winner, loser, tie, null, and regression transitions for the single
   allowed replay refresh if the selector fails; and
4. a frozen teacher ledger for hard `N=1` distillation if it succeeds.

MPAIL contributes the policy-prior interpretation; MPAIL2 contributes the
accumulated off-policy replay loop. Neither deployment-time MPPI nor a new
planner is introduced. Final deployment remains recurrent full-prompt `N=1`
pi0.5 with no external scorer.

## V7.1.4A — Compile the frozen selector without creating a new gate

This is a correctness repair required to execute V7.1.4B. It is not a separate
ranking study.

For candidate `i`, stock candidate `0`, supported outcome component `d`, and
ensemble member `k`, compute a paired difference

\[
\Delta_{i,d}^{(k)}
=
\hat y_d^{(k)}(z,u_i)-\hat y_d^{(k)}(z,u_0),
\]

then

\[
L_{i,d}=\operatorname{Mean}_k\Delta_{i,d}^{(k)}
-\operatorname{Std}_k\Delta_{i,d}^{(k)},
\qquad
U_{i,d}=\operatorname{Mean}_k\Delta_{i,d}^{(k)}
+\operatorname{Std}_k\Delta_{i,d}^{(k)}.
\]

Use the same ensemble index on the candidate and stock sides. Do not subtract
the marginal standard deviations of two independently assembled absolute
outcomes. With `K=5`, `[L,U]` is a frozen ensemble margin band / LCB heuristic,
not a calibrated statistical confidence interval. The words
`confidence-positive` below name the registered decision rule, not a coverage
claim.

### Frozen selector rule

- [ ] Mask `success_by_100` and `neg_damage` from predicted selection in the
  first run because their training targets are constant. Continue to measure
  real success and damage as hard behavior/safety outcomes.
- [ ] Use the supported registered component order
  `p_valid_100 -> q_valid_mean -> neg_tau_next`, with the already frozen
  replay-noise tolerances. Save `q@10/30/60/100` as diagnostic predictions;
  do not silently insert them into the first selector or call them a separately
  validated Tail-Q.
- [ ] Before comparison, project predictions to their registered target
  domains: `p_valid_100,q_valid_mean,q@h in [0,1]` and normalized
  `neg_tau_next in [-1.01,0]`. Record both raw and projected values; an
  unconstrained output outside the target domain cannot create artificial
  lexicographic headroom.
- [ ] For each candidate-versus-stock comparison, apply a ternary
  lexicographic confidence rule at every component:
  - `L > +tol`: confidence-positive and decisive;
  - `U < -tol`: confidence-negative and ineligible;
  - `[L,U]` contained within `[-tol,+tol]`: supported tie, continue to the
    next component;
  - otherwise: uncertainty crosses a decision boundary, so that candidate is
    ineligible.
- [ ] If every component is a supported tie, the candidate is tied and
  ineligible. If no candidate is confidence-positive, abstain and execute
  `u_0`.
- [ ] Among confidence-positive candidates, select the lexicographic maximum
  ensemble-mean supported outcome. Break an exact tolerance-level tie by the
  frozen SHA256 of `(run_id, source_id, decision, candidate_id)`.
- [ ] Emit one pre-outcome ledger row per anchor containing every component
  mean/std, paired interval, eligibility result, decisive component, selected
  family/candidate, abstention reason, and tensor/checkpoint hashes.
- [ ] Add a mechanical assertion that a masked head cannot be decisive and
  that the selector ledger is byte-frozen before the first candidate branch is
  executed.

Do not rerun or expand the old V7.1.3 ranking set as a launch condition. A
single tensor-only replay of the existing rows is allowed only to verify that
the compiled selector obeys these assertions; it is recorded as a unit test,
not new scientific evidence.

## Pre-registered failure routing

The prospective run must end in a method intervention or reusable replay, not
only a diagnosis report.

| Observed result | Next action |
|---|---|
| Full VLA pool has headroom, but LC is approximately matched permutation or abstains everywhere | Append the complete bank to the union; refresh the same outcome/Q ensemble once with the same architecture and frozen LCWM; use reserved `2301 + 10*k` sources for one final prospective selector test |
| Full VLA pool itself has insufficient headroom | Keep the scorer fixed; run one bounded proposal-support expansion using more canonical batches, shifted previous-chunk suffix/warm-start proposals, and atomic/distinct VLA proposals |
| LC selector passes prospectively | Freeze its pre-outcome ledger and launch V7.1.4C hard distillation immediately |
| Direct LC teacher works, but the hard student cannot reproduce it on train anchors | Use the new selected/sibling replay for one bounded redistillation under the same boundary; no representation or adapter sweep |
| Hard student fits train anchors but fails the reserved fresh sources | Record a coverage/generalization failure; use the single accumulated-replay refresh, then one final student run |
| Hard student improves but regresses on null states | From stock initialization, run one registered soft prior-preserving arm; no beta sweep |
| Hard or registered soft `N=1` beats stock and BC-only on fresh sources | Freeze one checkpoint and run one `5 tasks x 5 seeds` public-LoHo development matrix |
| The fixed replay refresh still leaves the prospective selector or student below its matched controls | End the current policy-improvement route with a bounded negative result; do not open a feature/EMA/LoRA/coupling sweep |

If the first selector fails and consumes `2301 + 10*k` as its post-refresh
evaluation family, reserve `2302 + 10*k` for the eventual fresh `N=1` student
gate. A source family is used for only one routing decision.

The single scorer refresh is defined now: keep `lc_full_selected.pt` frozen;
rebuild the expanded replay union; and train the same `K=5`, 768-256-256-9
outcome ensemble **from scratch** with the same heads, target transforms,
sampler, member seeds, optimizer, epoch budget, tolerances, margin multiplier,
and abstention rule. Only the replay rows change. Refreshing LCWM, adding a new
Q network, changing selector thresholds, or warm-starting a selected scorer is
outside this route. A later policy-only redistillation is a separate bounded
interface action and cannot be used to authorize a second scorer refresh.

## V7.2B — Train matched LCWM loss arms

### Common predictive graph

All arms instantiate the same real-prompt recurrent state and candidate path:

\[
z_t^\ell=U_\theta
\left(
T_\theta(z_{t-c}^\ell,E_{a,\theta}(u_{t-c})),
h_t^\ell
\right),
\qquad
\widetilde z_{ti}^\ell
=
T_\theta(z_t^\ell,E_{a,\theta}(u_{ti})).
\]

Every candidate-dependent head consumes only
`D_next(tilde_z_ti^ell)`. It cannot consume the current prefix, current
physical/task anchor, raw action, raw language, task/source/phase/family ID,
true next observation, or any direct action/language bypass. Language reaches
the transition through the complete `z_t^ell`; `T` receives no second language
input.

Repair the common self-prediction target in every arm. The existing V7.1.2c
target `EMA.initial_state(h_post)` is stateless and does not implement the
registered recurrent posterior. Instead unroll the EMA state over the same
observed history and define

\[
\bar z_t^\ell=\bar F(H_t,\ell),
\qquad
z_{ti}^{+,\ell}
=
\operatorname{sg}\!\left[
\bar U
\left(
\bar T(\bar z_t^\ell,\bar E_a(u_{ti})),
h_{ti,\mathrm{next}}^\ell
\right)
\right].
\]

Use the existing per-token latent predictor and cosine distance for one-, two-,
and three-block closure. This is a BYOL-style target mechanism adapted to an
action-conditioned recurrent transition; it is a common implementation repair,
not the loss variable being compared.

### Common base loss

Define

\[
\begin{aligned}
\mathcal L_{\mathrm{base}}
=\;&
\mathcal L_{\mathrm{closure}}^{1:3}
+
\mathcal L_{\mathrm{phys,abs}}
+
\mathcal L_{\mathrm{phys,ctr}}
+
\mathcal L_{\mathrm{sem}}
+
\mathcal L_{\mathrm{para}}
+
\mathcal L_{\mathrm{shared\text{-}phys}}.
\end{aligned}
\]

- `L_closure` predicts the recurrent EMA next posterior over one, two, and
  three executed blocks; latent distance alone is never a promotion metric.
- `L_phys,abs` uses the existing `D_next.d_q` and `D_next.d_obj` heads with
  dimension-mean Huber for supported EEF/proprio and object displacement.
- `L_phys,ctr` applies the same loss to candidate-centered within-anchor
  physical effects, in addition to rather than instead of absolute targets.
- `L_sem` uses the existing supported `valid_bits`, `event_bits`, `flips_01`,
  and `flips_10` heads under the query GoalSpec. Ordered prefix, progress, and
  milestone changes are derived readouts from these predictions for reporting,
  not silently added heads. Unsupported `event_bits` labels are masked.
- `L_para` symmetrically aligns the posterior and transitioned states for
  verified descriptions of the same goal, together with their predicted
  outcomes:

  \[
  \mathcal L_{\mathrm{para}}
  =
  d(z_t^{\ell_p},\operatorname{sg}[z_t^{\ell_q}])
  +
  d(\widetilde z_{ti}^{\ell_p},
    \operatorname{sg}[\widetilde z_{ti}^{\ell_q}])
  +
  \mathcal L_{\mathrm{immediate\text{-}sem\text{-}equiv}},
  \]

  with the two directions averaged. It does not force different goals apart
  by an arbitrary latent margin. This base term covers physical and immediate
  semantic predictions only; continuation `p/q` and scalar score equivalence
  follow the W0/W1/W2 detach routing rather than leaking into `L_base`.
- `L_shared-phys` makes the same `(history, action, physical next state)` retain
  the same physical prediction across compatible GoalSpecs while allowing
  task predicates and progress to differ.

No new contact, ordered-prefix, progress-change, or milestone head is added in
V7.2. If an implementation later adds a head, it is an architecture revision
outside these matched arms; it cannot be introduced only for one objective.

### End-to-end continuation-outcome loss

Do not call a single observed continuation label a Bellman Q target. For
candidate `i`, horizon `h in {10,30,60,100}`, and the two registered sibling
continuations, define empirical stock-policy outcomes

\[
\bar q_{tih}
=
\frac{1}{R}\sum_{r=1}^{R}q_{tihr},
\qquad
\bar p_{ti}
=
\frac{1}{R}\sum_{r=1}^{R}p_{ti,100,r},
\qquad R=2.
\]

Predict them directly from the transitioned state:

\[
\widehat q_{tih}=\sigma(D_q(\widetilde z_{ti}^\ell)),
\qquad
\widehat p_{ti}=\sigma(D_p(\widetilde z_{ti}^\ell)).
\]

Let `g=[p_valid_100,q@10,q@30,q@60,q@100]`. The outcome loss is

\[
\mathcal L_{\mathrm{out}}
=
\operatorname{Huber}_{0.1}(\widehat g_{ti},\bar g_{ti})
+
\operatorname{Huber}_{0.1}
\left(
\widehat g_{ti}-\overline{\widehat g}_{t},
\bar g_{ti}-\overline{\bar g}_{t}
\right).
\]

The first term anchors absolute continuation outcome; the second forces
within-state action effects instead of permitting a scene/phase prior. Average
dimensions, then candidates, anchors, sources, and tasks. The two repeats form
one empirical target and are never counted as two independent samples.
`q_valid_mean` is derived from the four horizons rather than supervised twice.

### Within-anchor ranking loss

Decode one scalar only from the transitioned state:

\[
s_{ti}=D_s(\widetilde z_{ti}^\ell).
\]

For this iteration the supported ground-truth tuple is frozen to
`p_valid_100 -> mean(q@10,q@30,q@60,q@100)`. For each sibling pair:

- both repeats prefer the same candidate: `y_ij in {-1,+1}`;
- both repeats call the pair tied within replay tolerances: supported tie;
- conflicting repeats, or one tie and one non-tie: unstable and masked.

Then

\[
\mathcal L_{\mathrm{BT}}
=
\operatorname{softplus}\!\left[-y_{ij}(s_i-s_j)\right],
\qquad
\mathcal L_{\mathrm{tie}}
=
\operatorname{Huber}_{0.1}(s_i-s_j,0).
\]

Give one half of each anchor's decided-pair mass to candidate-versus-`u0`
pairs and one half to all other decided pairs; normalize ties separately, then
anchor, source, and task. Pair count cannot amplify a candidate-rich anchor.

training: r1 contains `107` decided pairs over `5/18` anchors, but only four

### Ordinal-soft W2 teacher

Freeze `W2` and compute its pairwise win-rate statistic using only the scalar
rank head:

\[
r_i
=
\frac{1}{M-1}\sum_{j\ne i}\sigma(s_i-s_j).
\]

Convert the registered proposal-mixture prior into finite candidate weights:

\[
w_i(\beta)
=
\frac{\pi_{\mathrm{mix}}(i)\exp(r_i/\beta)}
{\sum_j\pi_{\mathrm{mix}}(j)\exp(r_j/\beta)}.
\]

The proposal-mixture prior is uniform over all manifest-valid VLA candidates,
`pi_mix(i)=1/M`; its resulting family mass is reported rather than tuned. Set
the fixed lower-bound temperature `beta_0=0.25`. For each anchor, begin at
`beta_0` and only **increase** beta, by deterministic bisection on
`[0.25,1000]` with tolerance `1e-6`, until the safety floor `ESS/M >= 0.5` is
met. Never decrease beta to manufacture concentration. If the upper endpoint
cannot satisfy the floor, use `beta=+inf`; exact or near ties therefore retain
the proposal prior naturally. Freeze every beta before any branch outcome is
read. There is no beta or family-prior sweep.
This is an MPAIL-inspired, prior-preserving finite-candidate heuristic. It is
not MPAIL, does not provide a KL-improvement theorem for the ordinal score, and
is being tested empirically here.

- [ ] Seal candidate tensors, model scores, `r_i`, `pi_mix`, `beta`, ESS, and
  weights in an outcome-blind teacher ledger before executing a candidate.
- [ ] Execute the complete teacher bank with common-noise continuations and

### Policy objective and arms

For a frozen teacher ledger, train only the executed first ten actions:

\[
\mathcal L_{\mathrm{policy}}
=
\lambda_{\mathrm{soft}}
\sum_i w_i\mathcal L_{\mathrm{FM},0:c}(u_i)
+
\lambda_{\mathrm{trust}}\mathcal L_{\mathrm{stock\text{-}trust}}
+
\lambda_{\mathrm{demo}}\mathcal L_{\mathrm{demo\text{-}FM}}.
\]

The unexecuted suffix receives no model-derived credit. Full demonstrations
retain ordinary full-chunk flow matching. Freeze each LCWM during its policy
run; policy loss never updates the world model in the first readout.

task/source/anchor or demonstration hierarchy, then fix
`lambda_soft=lambda_trust=lambda_demo=1`. Use `300` optimizer steps, AdamW
`lr=1e-4`, `wd=1e-4`, gradient norm `1.0`, and checkpoints/evaluation every
`50` steps for every trained arm. `L_stock-trust` is same-noise/time velocity
matching to frozen stock pi0.5 on the uncredited suffix and registered trust
states. `L_demo-FM` recurrently unrolls each full-prompt demonstration and
evaluates the adapted flow with `b=W_z(z_demo)`; a zero-bias stock forward that
makes the demo term constant is forbidden.

|---|---|---|---|
| `stock` | stock pi0.5 | none | deployment baseline |
| `BC-u0` | frozen `W2` | all target mass on `u0` + identical demo/trust | same-state BC/teacher-target control |
| `P0/no-WM-soft` | the same untrained recurrent initialization | frozen W2 teacher ledger | proposal-weighted post-training without world-model state learning |
| `W0-soft` | frozen `W0` | frozen W2 teacher ledger | base predictive-state treatment |
| `W1-soft` | frozen `W1` | the same W2 teacher ledger | outcome-loss state treatment |
| `W2-soft` | frozen `W2` | the same W2 teacher ledger | full proposed loss + model teacher |
| `W2-permutation` | frozen `W2` | matched-permutation ledger | candidate-identity control |

Using one W2 ledger for `P0/W0/W1/W2` deliberately fixes action supervision.
`W0-soft - P0/no-WM-soft` tests the common world-model base;
`W1-soft - W0-soft` and `W2-soft - W1-soft` test what the new losses did to the
