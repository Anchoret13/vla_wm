## What it says

**1. Updating the world model on new deployment data changed the deployed outcome by
nothing measurable.** `M1` vs `M0` is 39/288 against 39/288 with 21 discordant pairs
each way, p = 1.0000. That is the round's central question and the answer is flat.

**2. The action conditioning contributes nothing.** `M1` vs `M1_shuf` — the mandatory
no-action control, same data, same budget, same head, D1 action pairing broken within
matched strata — is 39 against 39 with 25 discordant each way, p = 1.0000. The model
being rolled forward under *the candidate action* rather than an arbitrary one makes no
difference to what the policy then does.

**3. Both nominal orderings that reach raw p < 0.05 point AGAINST the rolled-forward
model.** The same-data no-rollout control `Q` reaches 55/288 against `M1`'s 39/288
(p = 0.0328), and the matched-compute stale model `M0_cont` reaches 56/288 (p = 0.0241).
Neither survives Holm at m = 5, so neither is an established effect — they are reported
as directions, not verdicts. But there is no reading of this table in which the
rollout helps.

**4. The interface itself helps enormously, and that is not a world-model result.**
Every arm carrying a residual beats frozen pi0.5 by a large margin: 12/288 -> 39–56/288
on milestone-4 and 1/288 -> 20–33/288 on success. `M1` vs `base` survives Holm at
p_adj = 0.00015. But `base` and `rand` never receive the privileged `Phi'` annotation,
so `M1 vs base` measures *a bounded sustained residual, trained on a supplied progress
annotation, applied during the policy's stall* — not the world model. The pre-registration
says this explicitly and it is repeated here.

**5. Magnitude does not explain the ordering among the trained arms.** Their realised
\|delta\| spans 0.2197–0.2286, a 3.9% range, while milestone-4 spans 39–56, a 44%
range — and the LOWEST-magnitude arm (`Q`, 0.2197) is at the top. `rand` is the one
arm whose comparison is magnitude-confounded: it executed 0.313, **+39%** against the
trained mean, which is why the run-level check flagged it and refused to auto-report
contrasts. That flag was correct and the `M1 vs rand` line should be read with it.

## Every pre-registered refutation fired

From `2026-09-12.md`, "what would overturn a positive result", written before collection:

- *"`M1 vs M0` not significant while `M1 vs base` is — the gain is the interface and the
  data, not the updated dynamics."* — **happened**, p = 1.0000 against p_adj = 0.00015.
- *"`M1 vs Q` not significant — the gain is same-data supervision, not forward rollout."*
  — **happened**, and the sign is against `M1`.
- *"`M1 vs M1_shuf` not significant — the gain does not depend on action conditioning."*
  — **happened**, at exactly p = 1.0000.

## What would overturn THIS result

- **A second actor initialisation.** Only restart 0 of 3 was deployed per arm. Actor
  variance on this task is large: the calibration measured 4/24, 3/24 and 1/24
  milestone-4 across three independent random actors at one scale. The arms here differ
  by ~26% in residual output (measured before the run), so a null is exactly what a
  26% difference swamped by init variance would produce. **This is the replication the
  result needs and it has not been run.**
- A different advantage horizon. H = 10 was committed; H ∈ {5, 20} is a declared
  exploratory axis and is unrun.
- A `Phi'` head with more decision-region signal. The deployed head scored 0.389 on the
  decision region against 0.844 over all boundaries. An advantage built on a 0.389
  correlation is weak, and that weakness is shared by `M1`, `M0` and `Q` alike — so it
  cannot explain `M1 < Q`, but it does bound how much any of them could have shown.
- The inside placement, which is not a variant of this experiment but a different one.

## What this does NOT license

It does not license retiring chain3, and it does not license the claim that a latent
world model cannot help a VLA. It is one placement — the model **outside** the policy,
scoring imagined futures to weight a policy update — measured at n = 288 with its
controls. That placement has now been measured eight times in this project and has not
produced an attributable gain once. Framework §2's zero-initialised injection interface,
which exists to put the model **inside** the policy as a belief the controller
conditions on, remains unused.

## Addendum, 2026-09-16 — three things this report should have carried

Added when the round's open items were audited. Nothing here changes a number above;
each is a condition on how the table may be read, and each was recomputed from the
committed `outcome.json` files rather than copied from a log.

**1. The milestone-4 endpoint is non-contiguous, and this file never said so.** The
published counts reproduce exactly under "milestone 4 was reached at any point"
(`'4' in events`): base 12, rand 46, M0 39, M0_cont 56, M1 39, M1_shuf 39, Q 55, and
terminal success 1 / 33 / 20 / 23 / 21 / 25 / 28 — all seven arms, both endpoints.
They do **not** reproduce under the contiguous-prefix reading (`stage_reached >= 5`
gives 9 / 46 / 53 / 53 / 34 / 34 / 51). The distinction matters because this file
elsewhere argues that "a milestone reached without its predecessors is not progress
along the chain". The primary endpoint as registered and as computed does not impose
that; the contiguous reading is a different, unreported endpoint.

**2. The interface is not "small" at the deployed scale.** The trained arms executed
mean |delta| 0.2197–0.2286 over the panel, and the calibration that chose the scale
executed 0.440 in the basin, against a base command magnitude of 0.294 in the same
region (`2026-09-12.md:734,748` — a 09-12 measurement, not re-derived here). The
intervention is comparable to, and in the basin larger than, the command it corrects.
"A small policy interface on a frozen VLA" is a strained description of this arm, and
every statement about "the frozen policy plus a small correction" must carry it.

**3. D1's per-collector spread, since the pooled figure appears above.** Recomputed
from the four collector `outcome.json` files under the definition in point 1:

| collector | successes | milestone-4 |
|---|---|---|
| D1 i0 | 1/24 | 4/24 |
| D1 i1 | 5/24 | 6/24 |
| D1 i2 | 0/24 | 1/24 |
| D1 i3 | 1/24 | 2/24 |
| **pooled** | **7/96** | **13/96** |

(D0, frozen pi0.5 under the sigma sweep: 3/96 successes, 7/96 milestone-4.)

Successes range 0 to 5 of 24 across four collectors that differ only in their random
actor. That spread is the same order as the between-arm differences the round reports,
and it is the quantitative reason the single-restart null above cannot be read as a
null for the configuration — only for this initialisation.

**4. One published p-value does not come from its own table.** `M1 vs base` is reported
above as discordant 34/7 with p = 3.05e-05. The counts are right; the p is not. The
repository's own `exact_mcnemar` in `scripts/eval_v251_round.py` returns
**p = 2.532e-05** for (34, 7), cross-checked against `scipy` inside that function
(`scipy_agrees: True`) and recomputed by hand as
`2 * sum_{i<=7} C(41,i) / 2^41 = 2.53208e-05`. The published 3.05e-05 agrees to its
printed digits with `2^-15` = 3.0517578125e-05, the value a 16/0 discordant table would
give — a three-significant-figure log cannot establish that identity exactly, but it
does establish that the figure does not come from (34, 7) in this pipeline.
CLAUDE.md rule 5. Holm-adjusted over m = 5 the figure is
**1.266e-04**, not the 0.00015 reported.

Every other p in the primary table reproduces exactly from its own discordant counts:
`M1 vs M0_cont` 17/34 → 0.0240929, `M1 vs Q` 17/33 → 0.0328391, `M1 vs rand` 30/37 →
0.463818, `M1 vs M1_shuf` 25/25 → 1.0, `M1 vs M0` 21/21 → 1.0. Both endpoints'
per-arm counts also reproduce exactly (milestone-4 12/46/39/56/39/39/55, terminal
success 1/33/20/23/21/25/28), under the definition in point 1.

**The conclusion of the round is unchanged.** 2.53e-05 and 3.05e-05 are both far below
any threshold, the sign is the same, and `M1 vs base` was never the world-model
contrast anyway. What changes is that a number in a published table has been traced to
a pipeline that is not the one that produced the table, and it was found only because
the recomputation was run against the published values rather than trusted.
