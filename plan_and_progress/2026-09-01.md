## Audit corrections before any new deployment

The existing v235 policy ranking is not a valid preregistration for the fixed-scale
pool. Two implementation errors must be removed first.

1. **Actor/model coordinate mismatch.** v235 rolls a latent normalized with the
   updated model's `mu_m/sd_m`, then passes it directly to actors trained with
   their own `mu_a/sd_a`. The correct path at every imagined step is:

   ```text
   z_model → x_raw=z_model·sd_m+mu_m
           → z_actor=(x_raw-mu_a)/sd_a
           → Δ_actor
   ```

2. **Contaminated base-policy prior.** v235 fits its action prior on base and
   sustained-policy tapes together, then adds a held-out actor residual. This is a
   mixture-policy prior plus another residual, not frozen π0.5 plus residual. The
   shared prior must be fit on base-policy tapes only and frozen across all arms.

Additional contract repairs:

- blind score-only code must not accept or read deployed rates;
- stale and updated models share base normalization, prior, Φ, starts, actors,
  rollout horizon and random seeds;
- `M0_continue` gets the same additional optimizer budget as `M1`;
- action-shuffled and strict no-roll controls exist before a result is read;
- tape loader fails on task, latent dimension or chunk-length mismatch instead of
  silently skipping data;
- every input/model/actor/code artifact is content-hashed.

The input audit found two more leakage paths before execution:

- the action-diverse base tape is useful for fitting dynamics but is not a pure
  π0.5 action distribution, so `--head-tapes` is now a content-hash-checked subset
  of the base tapes; the rehearsal freezes its prior and Φ from the pure on-policy
  tape only;
- the two sustained policies reuse environment seeds 6400–6495. Splitting each
  tape independently put 38 seeds on both sides. v241 now hashes `role+env_seed`,
  so every occurrence of a scene is wholly train or wholly holdout (verified
  overlap: zero).

## EVOLVE-1: formal current-benchmark experiment

### Causal question

Does newly deployed data improve the next policy *through the updated latent
dynamics*, beyond extra SGD, state value, direct outcome fitting, action-blind
models and actor/model seed variance?

### One complete round

```text
π0 deployment → D1 sustained-policy trajectories
              → M0 / M0_continue / M1 / M1_action-shuffled
              → fixed-scale actor pools scored blindly
              → selected π1 deployed full-prompt, N=1
```

- `D0`: frozen chain3 baseline deployment tape.
- `D1`: two preregistered sustained residual collectors, 48 episodes each.
- `M0`: D0 only.
- `M0_continue`: D0 only, but the same extra optimization budget as M1.
- `M1`: warm-start M0 and update on balanced D0+D1 replay.
- `M1_action-shuffled`: same data/budget, but action pairing is broken within
  matched strata.
- `Q_no-roll`: same D0+D1 target/data, direct action-outcome scorer with no latent
  rollout; this is the strong same-data model-free selector.
- Two independent fixed-hyperparameter actor pools, eight actors per pool; only
  initialization differs. Model seeds `{17,29,43}` cross both actor pools.
- Each selector aggregates standardized scores across model seeds by median.
  Same selected actor means a registered zero contrast, not a rerun.
- Final evaluation deploys a single selected controller, not best-of-N at runtime.

The D1 behavior controllers do not yet exist. A repository-wide checkpoint audit
found no actor that is simultaneously `chain3_lr2`, rich-8217 and `c=10`.
Historical v205/v207/v230 actors are chain1b; the only actor files labelled
chain3 are legacy-2073 v185 artifacts whose external normalizer checkpoint is in
fact chain1b. Prior chain3 deployment of one such actor does not repair that
contract mismatch. The executable order is therefore strictly
`Gate0 PASS -> build/freeze rich M0 on canonical D0 -> build two fixed-hyperparameter
chain3 rich collector actors -> seal controller registrations -> collect D1`.
No historical chain1b/legacy actor may be silently reused as a D1 collector.
