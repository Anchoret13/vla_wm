# 2026-07-25 — LC-Flow v0.4 Action Plan

## Decision

Keep the current LC-Flow architecture. Do not restart the framework and do not
make additional branch collection the immediate objective.

The next milestone is an existing-data vertical slice that demonstrates:

1. recursive next-latent prediction;
2. grounded reward/value and action-effect prediction;
3. a policy-improvement target generated by the learned world model;
4. a better final `N = 1` VLA, rather than only better branch imitation or
   reranking.

---

## P0 — Freeze the method and data contract

- [ ] Treat `framework_design.md` as the active design record.
- [ ] Preserve the current `LCState`, action encoder, `T/U` prior-posterior
  structure, and zero-init AdaRMS injection.
- [ ] Remove the old immediate assumption that `128–256` new branches must be
  collected before the next method experiment.
- [ ] Record data roles in code/config:
  - ordinary sequential trajectories: recursive dynamics, reward/value,
    rehearsal;
  - snapshot branches: alternative-action effects, ranking calibration,
    GT-teacher control;
  - language relabels: shared physics and task-relative readout;
  - future interaction: conditional targeted coverage only.
- [ ] Keep the full-prompt, `N = 1` policy as the primary endpoint.

**Exit condition:** the trainer and evaluation configuration no longer encode
branch-FM as the only policy-learning path or branch data as the only dynamics
data.

## P1 — Build the sequential predictive-state batch

- [ ] Expose `next_prefix_hidden_full` through the training data path.
- [ ] Add ordinary trajectory windows from the existing LIBERO/chain rollouts.
- [ ] For each decision boundary, provide:
  - current prefix feature and recurrent state context;
  - executed first-ten action block;
  - next prefix feature;
  - reward/progress/predicate labels;
  - continuation return or remaining trajectory when valid;
  - instruction and paraphrase/goal metadata;
  - source episode and split group.
- [ ] Support two- and three-block windows, but keep `k = 1` as the first run.
- [ ] Ensure train/dev/test grouping is by source episode; branch siblings and
  language relabels from one physical source must remain in one split.
- [ ] Verify that terminal success, progress, and continuation labels are
  captured before environment reset.

**Artifact:** one loader smoke test that prints aligned
`(z_t, a_{t:t+10}, next-prefix, reward/progress, source-id)` shapes and verifies
that no source group crosses splits.

## P2 — Add recursive latent prediction

- [ ] Add an EMA target copy of the posterior state encoder/update.
- [ ] Maintain the EMA target carry along each observed trajectory and construct
  the next posterior from the target prior plus the stored next-prefix feature;
  do not treat the next-prefix feature alone as the complete target state.
- [ ] Add a small prediction projection and
  `L_self_1 = d(predicted_prior, stopgrad(next_posterior))`.
- [ ] Keep physical/task outcome heads active so the self-predictive state cannot
  solve training only through a collapsed target.
- [ ] Log target variance, predicted-state variance, and effective rank as
  collapse monitors.
- [ ] Add trivial evaluation baselines:
  - copy current state;
  - ignore action;
  - predict the mean next state.
- [ ] Only after held-out `k = 1` signal, add open-loop `k = 2,3` rollout loss.

**Exit condition:** held-out one-step prediction beats all trivial baselines and
the learned target remains non-collapsed. This is a structural gate, not the
final scientific result.

## P3 — Repair outcome, reward, and value semantics

- [ ] Keep the current absolute physical-effect heads.
- [ ] Keep sibling-centered branch effects as an additional contrast loss.
- [ ] Mask each physical channel using its own resolution flag; do not use a
  group-level q/object AND gate.
- [ ] Separate the current `ret` semantics into:
  - one-block task reward;
  - phase-aware progress;
  - terminal/success probability;
  - policy-dependent continuation value.
- [ ] Define the first value target explicitly as \(V^{\pi_0}\).
- [ ] Audit available trajectory continuation lengths and choose MC,
  TD(\(\lambda\)), or FQE-style targets.
- [ ] Record the generating policy for every value target.
- [ ] Add cross-language physical consistency and paraphrase-equivalent outcome
  losses using existing stored histories before collecting new interaction.

**Exit condition:** every output head has one documented target definition and
one held-out metric; no classifier is described interchangeably as reward,
return, and value.

## P4 — Train the existing-data world-model vertical slice

- [ ] Mix ordinary sequential windows with existing branch groups.
- [ ] Start with:
  - `L_self_1`;
  - absolute physical/task effects;
  - sibling-centered effect loss;
  - reward/progress;
  - \(V^{\pi_0}\);
  - demo rehearsal.
- [ ] Keep the policy adapter at stock/no-op during the first world-model run.
- [ ] Evaluate on held-out source episodes:
  - next-latent prediction;
  - task-object effects;
  - predicate flips/progress;
  - reward/value calibration;
  - candidate pairwise accuracy and top-1 regret.
- [ ] Compare candidate ranking against:
  - progress-only scoring;
  - action-marginal scoring;
  - the current effect-only v3 checkpoint.
- [ ] Add `k = 2,3` rollout only after the `k = 1` run is interpretable.

**Promotion condition:** recursive prediction and grounded effect prediction must
both show held-out signal, and branch ranking must improve over non-world-model

## P5 — Implement model-guided policy distillation

- [ ] Sample candidate action chunks from frozen π0.5 first; later compare the
  current LC-Flow policy as proposal distribution.
- [ ] Score only the executed/replanned first-ten block:

  \[
  \hat Q(z,u)
  =
  \hat r(z,u)
  +
  \gamma^{10}\hat V(T(z,u)).
  \]

- [ ] Calibrate predicted candidate ordering on real held-out branches.
- [ ] Use a conservative positive-advantage weight with:
  - positive margin;
  - temperature;
  - maximum clipping;
  - optional ensemble/checkpoint-disagreement penalty.
- [ ] Apply model-guided flow loss only to the first ten actions.
- [ ] Retain full-chunk demonstration rehearsal.
- [ ] Keep real positive-branch FM as a separate `GT-branch teacher` arm.
- [ ] Initially freeze or slow the world model while distilling its targets.

**Required comparison:**

| Arm | Purpose |
|---|---|
| stock π0.5 | base policy |
| GT branch-FM | observed better-action imitation |
| LC-Flow, no world loss | matched recurrence/capacity |
| effect-only v3 | current checkpoint |
| LC-Flow v0.4 + model-guided FM | full method |

## P6 — Cheap policy readout after every promising checkpoint

- [ ] Run paired full-prompt chain3 `N = 1` evaluation.
- [ ] Report SR, Q, per-atom completion time, and the first unresolved atom.
- [ ] Pair policy flow noise wherever the architectures permit it.
- [ ] Measure first-ten action shift from the stock policy.
- [ ] Run a small LIBERO-10 retention check before any multi-seed promotion.
- [ ] Do not use best-of-N improvement as evidence that the final VLA improved.

**Diagnosis:**

- negligible action shift → test adapter influence, then consider action-expert
  PEFT;
- action shift without Q/SR gain → inspect model score and candidate support;
- model ranking good but distillation bad → inspect flow weighting/credit;
- policy gain with no-world-loss control tied → claim policy adaptation, not
  world-model benefit.

## P7 — Conditional late-chain data collection

Do not collect new branches merely because cream cheese is the known failure
phase. First localize the failure with the v0.4 model.

Collect approximately `16–32` independent late-chain source episodes only if at
least one condition holds:

- model uncertainty is concentrated after soup+sauce completion;
- held-out cream-cheese candidate ranking is worse than early-chain ranking;
- nominal self-prediction is good but alternative-action effect prediction is
  unsupported;
- sampled π0.5 candidates contain a useful action that the model cannot rank;
- the modified policy visits states outside the stock-rollout data.

For a triggered collection:

- [ ] prioritize post-soup+sauce histories and cream-cheese recovery/transport;
- [ ] save multiple policy-supported action candidates and exact flow noise;
- [ ] retain repeated `(snapshot, action)` restore checks for noise calibration;
- [ ] include genuine positive full-goal actions, not only grasp-phase object
  displacement;
- [ ] relabel stored physical continuations under compatible goals and
  paraphrases offline;
- [ ] stop after the first batch and rerun P4–P6 before expanding.

# Execution log (Claude) — P1, written before building

Contract facts this design rests on (verified against code today):

- `LCState.posterior/step` consume the **full real-prompt prefix** `[B, P, 2048]`
  + bool mask (P may vary across episodes; must be constant within one);
  `unroll_lc_history` reads exactly `history_prefix_hidden/mask/action_norm`,
  keeps state across the episode, truncated-BPTT window at the tail.
- `seq_libero_10_v2` has per-decision labels (q, obj_pos, predicate bits,
  success/terminal, `first_success_t`, terminal record appended **before any
  reset** — the P1 label-capture requirement is already satisfied there) and a
  **sealed** split manifest (train/dev usable; audit stays sealed), but stores
  only pooled 128-token features — unusable as posterior input.
- The v2 builder re-renders frames at 360×360 by deterministic replay
  (restore `states[0]` + step raw HDF5 actions); it already runs the
  real-prompt prefix forward per decision and pools afterward. Full-prefix
  capture is therefore the same replay loop minus the pooling — live-eval
  parity, no 128×128 HDF5-image distribution shift.
- Demo actions are raw env-convention; policy normalization is plain
  mean/std (`(a − μ)/(σ + 1e-8)`, stats in the pretrained repo's normalizer
  safetensors; verified bit-identical via the runner's own
  `NormalizerProcessorStep`). `E_a` consumes normalized blocks `[B,10,7]`.

## P2 v1 result: Gate A FAIL (structural, three localized causes)

`results/self_predict_v1/history.json`, final (epoch 29): train self-loss
0.0007, **0/6 dev sources beat all baselines**.

- **Joint collapse**: EMA-target effective rank 9.1/1536 (declining
  monotonically 13.9 → 9.1 across evals), min per-dim std 1.04e-2;
  predictions worse (rank 4.96, mean std 4.9e-3). No BYOL-style asymmetry
  survives batch-1 episodes with no augmentation — the online/target pair
  drifted into a low-rank subspace together.
- **Action pathway unused**: model distance == ignore-action distance to
  ~1e-5 on every source (e.g. 0.00052 vs 0.00052) — a near-constant target
  makes T(z, a) ignore a.
- **Copy-state dominance**: copy beats the model 2–4× on all six sources
  (all absolute distances ~1e-4–5e-4); absolute cosine distance cannot see
  one-step structure when consecutive targets barely move.
- Outcome-loss scale defect confirmed: per-dim std over mostly-static
  transitions turns rare grasp-phase motion into normalized outliers
  (train out-loss 3226 → 289, still ~100× too large).

## P2 v2 registration (written before implementation/run)

One iteration, three changes, each tied to a measured cause; framework Gate-A
fail-path compliance ("inspect target construction / EMA / alignment" —
alignment verified correct; no new data, no architecture change):

1. **Variance–covariance regularization on the online posterior** (VICReg
   form): per-dim hinge variance max(0, 1 − std)² weight 1.0 + off-diagonal
   covariance penalty weight 0.01, computed over each episode's online
   posterior states. Targets inherit online rank through EMA → halts the
   measured rank decay. EMA tau unchanged (0.996).
2. **Residual objective + Δ-space Gate-A metric**: auxiliary loss
   ‖(p(T(z,a)) − z⁺_t) − (z⁺_{t+1} − z⁺_t)‖² / (‖z⁺_{t+1} − z⁺_t‖² + ε),
   weight 1.0; primary held-out metric becomes Δ-space normalized error
   where copy-state ≡ 1.0 by construction and ignore-action uses the same
   formula with a zero-action prior. Gate A v2 rule: Δ-space model error
   < 1.0 (beats copy) AND < ignore-action, per dev source; absolute-space
   numbers still reported.
3. **Outcome scales from the LOCKED v2 physical table + Huber(δ=4)**:
   q dims scale [EEF pos 7.344e-3 ×3, quat 5.451e-3 ×4, gripper 2.598e-4
   ×2], object 1.175e-3 — the already-locked effect-centered scales instead
   of data-fit std; Huber caps residual outliers.

Output: `results/self_predict_v2`. Same data, same splits, same seed.

## P2 v3 registration (written before implementation/run)

Framework Gate-A fail-path sanctions target-construction repair. Two changes,
both aimed solely at the measured variance loss; everything else frozen
(same data/splits/seed, same Δ-gate rule, same distances, same scales):

1. **Cross-episode VIC batch**: accumulate gradients over 4 episodes per
   optimizer step and compute the variance/covariance penalty on the pooled
   online states of those 4 episodes. The v2 per-episode penalty conflated
   temporal correlation within an episode (physical) with cross-sample
   collapse (pathological); pooling across episodes regularizes the right
   variance.
2. **Canonical VICReg weights**: var 25.0, cov 1.0 (v2's var 1.0 measurably
   lost; 25/1 is the standard published ratio — adopted as-is rather than
   tuned).

Output: `results/self_predict_v3`. Gate A v3 rule identical to v2 plus:
target effective rank must be non-decreasing over the final three
evaluations (an explicit numeric collapse criterion instead of judgment).

## P2 v3 result: Δ-criteria PASS 6/6 again; explicit rank criterion FAIL

`results/self_predict_v3/history.json`, epoch 29: Δ-gate 6/6
(model_delta 0.157–0.651, all < copy-state 1.0 and < ignore-action);
min per-dim std 4.05e-2 (4× v2 — the pooled canonical-weight VIC works);
but target effective rank over the final three evals = 13.3 → 11.1 → 9.4,
**decreasing** → the registered v3 rank criterion fails. A transient
destabilization at epoch 19 (self 0.054, deltas up to 17.6) recovered by
epoch 24 — recorded.

**Status: Gate A not claimed after three registered iterations.** What is
established: the Δ-space one-step criteria pass decisively and repeatedly;
action-conditioning is present (consistently beats the zero-action prior);
variance can be defended at the level the regularizer targets. What is not:
a non-shrinking target. Open question referred to the review loop (it is
the framework's own open [DEC] "exact EMA target projection and latent
distance"): whether the collapse criterion should be evaluated in a smaller
learned target projection (e.g. d=64) matched to the state's intrinsic
capacity, rather than demanding non-decreasing rank in the full 1536-dim
flattened space. Recommendation: adopt the smaller learned projection (the
framework fail-path's own remaining prescription) — awaiting review before
a fourth iteration. P3 proceeds meanwhile (ungated implementation).

## P3 value-target audit (run before choosing the [DEC], as required)

`scripts/audit_value_targets.py` on the existing data:

- cache demo episodes: 18/18 reach success; generating policy = **expert
  demonstration** (not π0); lengths 238–388 actions;
- branch continuations: 52, **0% success**, lengths 60–160, generating
  policy = frozen π0.5 under recorded atomic prompts;
- chain terminal outcomes exist only in the exam protocol records, not
  aligned to stored histories; chain histories store no per-decision
  bits/positions.

**Consequences (registered):** a success-based MC `V^{π0}` from current π0
continuations would be the constant-0 classifier the v0.4 audit explicitly
bans — so the success-based value head is NOT trainable from current data
and is deferred. P3 v0 therefore defines:

1. one-block reward `r_t` = goal-atom completion delta (bits_{t+1} −
   bits_t summed over active atoms), available on cache episodes;
2. phase-aware progress `p_t` = fraction of goal atoms true + per-atom
   object-to-receptacle distance (obj_pos and basket stored);
3. terminal/success probability head trained where real label variation
   exists (demo episodes contain within-episode predicate flips — unlike
   the branch data);
4. `V^{π0}` v0 target = discounted atom-completion return along **π0-
   generated chain source episodes**, which requires a deterministic
   relabel pass: replay the 7 chain source episodes (same seed + recorded
   noise reproduce them exactly) capturing per-decision q/obj_pos/bits
   aligned to the stored histories. This adds labels to already-used
   episodes — no new interaction states — and every value target records
   its generating policy (π0.5 full prompt). Expert-demo returns are kept
   only as a separately-labeled upper-bound diagnostic, never merged with
   π0 value targets.

## Established vs not established (P2, honest reading)

Established: in two configurations on the same data/split/seed, the real-action
online transition predicts its EMA action-conditioned target better than the
matched zero-action transition in delta space.

Not established: improvement over mean-next, grounded held-out physical
prediction, or a non-shrinking EMA target. The result therefore does not yet
certify recursive predictive closure or real-world action dynamics, and Gate A
remains failed / unclaimed.

## EOD projection question — no longer a standalone P4 blocker

Whether the collapse criterion should be evaluated in a smaller learned
target projection (e.g. d=64) matched to intrinsic state capacity, rather
than as non-decreasing effective rank of the full 1536-dim flattened state.
The review recommendation is **not** to run a fourth standalone Gate-A
iteration merely to satisfy this criterion. Full-state and smaller-projection
self-prediction should instead be compared as P4 arms under grounded
effect/ranking metrics. This recommendation does not claim Gate A passed; it
prevents the unresolved rank metric from becoming another diagnostic-only
workstream.

## A1 — Lock the policy-improvement target

Current targets cannot repair the observed late-chain failure:

- `r` is an atom-completion flip;
- implemented `p` is only the fraction of completed atoms;
- \(V^{\pi_0}\) is discounted atom-completion return under the frozen full-prompt
  π0.5 rollout;
- every recorded π0 chain rollout ends at `2/3`, with cream cheese incomplete.

In the current train/dev chain loader, only three labeled states have two atoms
complete, and all three have \(V^{\pi_0}=0\). During cream-cheese approach,
grasp, lift, and transport, the existing targets are therefore
`r=0`, `p=2/3`, and `V=0`. Moreover, the current P5 score
\(\hat r+\gamma\hat V\) does not consume `p` at all.

- [ ] Define a phase-aware state potential for the active atom:

  ```text
  approach → stable grasp → lift → transport → placement
  ```

- [ ] Use lexicographic phase ordering or an explicitly documented
  potential-shaping term; never use raw object-to-basket distance across all
  phases.
- [ ] Preserve already completed atoms as a hard no-damage condition.
- [ ] Keep true one-block reward, phase progress, composite success, environment
  termination, and \(V^{\pi_0}\) as separate targets.
- [ ] Specify how phase progress enters the model score used by P5, for example:

  \[
  \hat Q_{\mathrm{score}}(z,u)
  =
  \hat r(z,u)
  +
  \lambda_\Phi\,\widehat{\Delta\Phi}(z,u)
  +
  \gamma_{\mathrm{decision}}\hat V(T(z,u)).
  \]

- [ ] Resolve the discount convention: current value targets use
  `gamma_decision = 0.99`, while the design writes `gamma^10`. Use
  \(\gamma_{\mathrm{decision}}\) once per ten-action decision, or derive it
  explicitly from a per-environment-step discount.

**Exit condition:** on hand-checked cream-cheese transitions, correct
approach/grasp/lift/transport is not labeled negative merely because
object-to-basket distance temporarily increases, and the P5 score consumes the
same documented semantics used for its held-out ranking labels.
