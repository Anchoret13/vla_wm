---

## Decision

Keep the problem formulation, complete transitioned `z_t^ℓ`, frozen π0.5
action prior, and recurrent full-prompt `N=1` deployment endpoint fixed. Do not
switch to deployment-time MPC/MPPI, online best-of-N, or a policy trained from
scratch.

V7.0 is a bounded oracle bridge, not a replacement research objective. It asks
whether a genuinely better action already inside a registered VLA proposal
family can be transmitted through `z_t^ℓ → π0.5` without a global policy
shift. A learned LCWM scorer remains the mainline endpoint. V7.0 may stop before
training only for a data-integrity failure or absence of any mechanically
eligible VLA signal after the one bounded proposal retry. Failure of the
conservative claim gate alone must not turn the run into another support
report.

[MPAIL](https://arxiv.org/abs/2507.21533) motivates a prior-regularized
improvement distribution

\[
q_\beta(u\mid H_t,\ell)
\propto
\pi_0(u\mid H_t,\ell)
\exp\!\left(s(u)/\beta\right).
\]

For exchangeable candidates sampled from the frozen canonical policy, the
prior is already represented by sampling. The finite-candidate weights are

\[
w_i
=
\frac{\exp(s_i/\beta)}
     {\sum_j\exp(s_j/\beta)}.
\]

No π0.5 flow density is estimated or multiplied into these weights. A
noncanonical proposal mixture requires separately registered family weights
and is not the same canonical-prior update.

This is an MPAIL-inspired Monte-Carlo policy update, not an implementation of
MPAIL. The paper uses a cardinal trajectory cost and deploys an online MPPI
planner. Here `s` is an ordinal executed-outcome score and the endpoint is a
distilled full-prompt `N=1` flow policy. Accordingly, the soft teacher is an
ordinal-soft heuristic; its temperature does not create a KL-improvement
theorem.

The candidate-source distinction is fixed before the audit:

| candidate family | V7.0 role |
|---|---|
| canonical full-prompt π0.5 samples | clean π0.5-prior improvement test |
| atomic/subgoal/distinct-goal π0.5 samples | explicit proposal-augmented VLA diagnostic |
| scripted servo | reachability/oracle-headroom upper bound only; never a V7.0 distillation target |

The first training comparison is anchor-hard oracle versus a matched hard
random control, crossed with the current affine versus a centered recurrent
coupling. Soft weighting is added only on the behaviorally winning coupling.
Only executed anchor behavior can select the next route.

## V7.0.1 — Measure oracle headroom by proposal family

Construct one frozen anchor table containing `u_0`, all canonical candidates,
all atomic/distinct-goal VLA candidates, servo, losers, ties, null candidates,
and their sibling-CRN continuations. Exact replay branches remain audits and
never enter a proposal pool.

Use the registered paired outcome ordering rather than immediate geometry. For
the canonical candidate pool `C` at one anchor, define the Borda-style oracle
preference score

\[
s_i^{\mathrm{GT}}
=
\frac{1}{|\mathcal C|-1}
\sum_{j\neq i}
\operatorname{pref}_{\mathrm{CRN}}(i,j),
\qquad
\operatorname{pref}_{\mathrm{CRN}}(i,j)\in\{-1,0,1\}.
\]

This is an ordinal preference score, not a return or Q estimate. It preserves
the registered priority over success, damage, valid progress, and
multi-horizon continuation outcomes without inventing a Euclidean reward.

For the expanded diagnostic, freeze proposal-family mass before scoring:

```text
α_canonical = 1/3
α_atomic    = 1/3
α_distinct  = 1/3
```

Use `m_j=α_f/n_f` both when averaging pairwise opponents,

\[
s_i^{\mathrm{GT,mix}}
=
\frac{\sum_{j\ne i}m_j\operatorname{pref}_{\mathrm{CRN}}(i,j)}
     {\sum_{j\ne i}m_j},
\]

and later when constructing soft weights. This prevents the arbitrary number
of candidates in one family from changing another candidate's Borda scale.
The expanded pool is therefore a registered proposal-mixture experiment,
never a canonical-π0.5 prior claim.

  m_i=\alpha_{f(i)}/n_{f(i)},

- [ ] Permute weights within positive anchors only with frozen seed `70002`;

## Next mainline — V7.1 correction-aware off-policy LCWM/Q

[MPAIL2](https://arxiv.org/abs/2602.24121) motivates the later separation of
proposal, latent transition, transition reward, tail value, and off-policy
replay. MPAIL2 itself learns task-agnostic dynamics and primarily executes a
planner; neither choice is adopted here. V7.1 retains language-conditioned
`z_t^ℓ` and the recurrent full-prompt `N=1` policy endpoint.

The current correction bank is not yet world-model replay. It stores action
chunks, physical summaries, semantic outcomes, and continuation scores, but
not complete branch/continuation observations. V7.1 therefore starts by
materializing real `(o_t,a_t,o_{t+1})` transitions rather than pretending the
existing outcome files can supervise latent dynamics.

- [ ] Deterministically re-reach every strict-clean V6.9.2 anchor and re-execute
  the registered candidate/continuation bank, or recollect it if re-reach
  fails. Store raw external/wrist observations, proprioception, normalized and
  environment actions, posterior observations, GoalSpec labels, outcome tuple,
  CRN, and canonical/atomic/distinct/servo/winner/loser/tie/null provenance.
- [ ] Keep physical transitions deduplicated from language relabels. Store raw
  frames or language-independent visual tokens so the same physical future can
  be paired with every compatible task/paraphrase without copying a stale
  prompt-conditioned VLA feature.
- [ ] Train one correction-aware LC predictive checkpoint on accumulated demo,
  source, branch, loser, tie, null, and continuation transitions. Include
  multi-step latent prediction plus physical and task-semantic transition
  heads; positive oracle candidates alone are not a world-model dataset.
- [ ] Cross each shared physical transition with compatible GoalSpecs. Enforce
  same-goal paraphrase consistency in the task-conditioned predictive state,
  allow different valid goals to produce different semantic states, and keep
  the physical-future head invariant to instruction swap. This is the LCWM
  hypothesis; MPAIL2's task-agnostic representation is only a baseline.
- [ ] Freeze that predictive checkpoint for the first scorer experiment. Train
  a task-conditioned multi-head outcome/ordinal ensemble before inventing a
  scalar return: predict the registered success, damage, valid progress,
  milestone-time, and continuation components and derive pairwise preference
  under the frozen lexicographic contract.
- [ ] Train a task-conditioned distributional tail-value ensemble from the
  stored multi-horizon continuations, predicting the same outcome vector under
  the frozen stock continuation policy. Use lexicographic lower-confidence
  comparison for the first action selector. A scalar
  `Q_ℓ^{π_0}(z,u)` is permitted only after its outcome scalarization is
  separately registered; do not silently turn geometric progress into return.
- [ ] Evaluate canonical ranking and calibration on source-held-out candidates,
  including winners, losers, ties, and null anchors. Compare with proprio-only,
  proposal-prior, shuffled-language, and matched-permutation controls; these
