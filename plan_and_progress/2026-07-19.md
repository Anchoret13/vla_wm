## Feature-shift visualization (tap-source [DEC] diagnostics)

`scripts/viz_feature_shift.py` → `results/viz/feature_shift/`. On frames from a
libero_10 t0 rollout (t = 0 / 80 / 160), compared last-layer image-token features on
the SAME frame under three prompts: **real** instruction, **const** tap prompt
("do the task"), **alt** = a different task's instruction (content-specificity control).
Outputs: per-camera 16×16 cos-dist heatmaps overlaid on frames, joint-PCA token
displacement, per-token histograms, `summary.json`.

### Findings (revise yesterday's alarm)

1. **Heavy-tailed, not uniform**: most tokens are ~prompt-invariant (mode < 0.05
   cos dist); the 0.20 mean is driven by a shifted minority (tail to 1.2+).
   Language mixing hammers a few tokens, it does not rewrite the scene encoding.
2. **Content-agnostic magnitude**: alt-instruction shift ≈ const shift at every
   timestep (e.g. t0 agentview 0.243 vs 0.227); shift-map spatial corr const-vs-alt
   0.38–0.69. Two *real but different* instructions do not differ more than
   real-vs-const → the perturbation is "any prompt change", not instruction content.
3. **Speckled, not object-localized**: hot tokens scatter over background/arm/objects,
   not concentrated on task-relevant objects. PCA shows a prompt-shared manifold
   holding most tokens; the jumpers between clusters are the heavy tail
   (register/attention-sink-like, likely not object-semantic carriers).

## §11.1 same-frame prompt controls — RESULT (commit `TBD`, results/feature_controls/)

Same frames (t=0/80/160 of a t0 rollout), seven prompts: canonical t0, 3 paraphrases,
t1 (same LIVING_ROOM_SCENE2, different target objects), t2 (unrelated), constant.

| vs canonical t0 | mean cos dist (t0/80/160) | tokens >0.3 (t0) |
|---|---|---|
| paraphrases ×3 | **0.013–0.063** (p50 ~0.005) | 1–4% |
| t1 same-scene | **0.403 / 0.197 / 0.414** (largest) | 40% |
| t2 unrelated | 0.279 / 0.139 / 0.320 | 25% |
| const | 0.271 / 0.117 / 0.299 | 25% |

Findings (REVERSES yesterday's "content-agnostic" read — which was an artifact of
having only one alt-task control):

1. **Paraphrase invariance is already in the frozen backbone**: same task, different
   wording moves features 7–10× less than any task change; residual paraphrase
   directions ~orthogonal to task-change directions (cos 0.05–0.3).
2. **Features are most sensitive to the decision-relevant distinction**: t1 (same
   scene, only target objects change) shifts MORE than a fully unrelated task.
   The last layer encodes which objects matter → **H_task stream carries real value**.
3. **const ≈ t2 in magnitude AND direction** (dir cos 0.57–0.73, highest pair):
   constant prompt ≈ removing task info → supports const last-layer as an H_world
   candidate (task-neutralized view).
4. δ(t1) shares ~0.5 direction with δ(const)/δ(t2) (generic component) plus a large
   non-shared task-specific component. Whether it localizes on target objects →
   pending segmentation masks (in progress).
5. SigLIP pre-trunk prompt-invariance maxdev = exactly 0.0 (sanity + determinism).
6. Corrected joint-PCA (shared centering, EV 0.59+0.10): conditions share one
   manifold; t1 re-codes a token subset (large jumps), rest stay put.

Framework implication: §0's required representation behavior (paraphrase→same,
task→different-and-decision-relevant) already holds at the frozen-feature level;
the 10-way task normalizer has strong backbone support.

## Independent review / audit — 2026-07-20 (Codex)

Bottom line: §11.1 provides enough evidence to set the dual tap as the **v0
implementation default**, but not enough to close the scientific tap `[DEC]` as
`RESOLVED / CONFIRMED`.

```text
PROVISIONAL v0 DEFAULT
  H_world = SigLIP pre-trunk
  H_task  = canonical-prompt last layer
  online  = one canonical-prefix pass

STILL OPEN
  cross-layout world-state decodability
  object-role selectivity
  heavy-tail token filtering
  task-conditioned next-state / predicate / candidate-ranking value
```

### Evidence that survives the audit

1. **SigLIP prompt invariance is high-confidence.** `maxdev = 0` follows from the
   pre-language architecture and is verified by the control. It is the cleanest
   `H_world` input.
2. **Canonical last-layer features are task-sensitive with preliminary paraphrase
   consistency.** On the same three frames, paraphrases move the canonical features
   by mean cos distance `0.013–0.063`, while the same-scene t0→t1 task swap moves them
   by `0.197–0.414`. This strongly supports retaining real-prompt last-layer tokens as
   an `H_task` candidate.
3. **The one-pass choice is a sound engineering default.** One canonical prefix can
   expose SigLIP tokens, task-conditioned last-layer tokens, and the sampling KV cache;
   the constant+real two-pass design has no demonstrated benefit that justifies its
   latency.
4. **Token-level inputs retain more usable spatial information than global
   mean-pooling.** The current evidence supports cross-attention over tokens, although
   it does not yet establish generalization to unseen layouts.

The tap default is therefore justified mainly by structural invariance + one-pass
cost + same-frame task sensitivity—not by a statistically significant difference
between object-position probe scores (`0.650` vs `0.645`).

### Audit findings that weaken the current wording

1. **Progress table and final JSON disagree.** This file reports SigLIP
   phase/remaining R² `0.90/0.84 (best)`, while `results/probe_ladder.json` contains
   `0.609/0.594`. The final JSON gives const-LL phase `0.824` and real-LL remaining
   `0.744`; the current `best` statement is reversed.
2. **Frame-split localization is interpolation, not layout generalization.** Adjacent
   frames from the same demonstrations are randomly split across train/test. The
   frame-split locprobe R² (`siglip/const/real = 0.650/0.600/0.645`) shows that position
   information is accessible within seen layouts. The actual demo-heldout locprobe
   results are all negative (`−0.371/−0.656/−0.601`) and cannot yet be dismissed as
   irrelevant data starvation.
3. **`LocProbe` is not a linear probe.** Its learned token scorer is followed by a
   spatial softmax and object-specific affine readout. The correct claim is
   `spatially-aware probe decodability`, not strict linear decodability. It also lacks
   repeated seeds / error bars; the moving-dimension mask is selected from test-label
   variance, and ridge λ selection slices through correlated frames.
4. **Selectivity evidence is suggestive, not confirmatory.** The PNG overlays raw
   frames while `LiberoProcessorStep` rotates the policy/token view by 180 degrees, so
   the displayed frame and token-space masks are not in the same orientation. The
   numeric group means may still be aligned in processed coordinates, but they use
   coarse, overlapping fixed-radius disks and highly unequal patch counts. At t=0,
   `rest = 0.452` exceeds both target groups; at t=160, distractor/rest shifts are
   comparable to targets. This does not support the word `precisely` across the
   rollout.
5. **Phase / remaining labels are not task progress or continuation value.** They use
   the full HDF5 action length `T`, while replay can terminate successfully before
   `T`. Store `first_success_t`, `actual_terminal_t`, and per-step BDDL predicate bits
   before interpreting these probes as progress or steps-to-success.
6. **`e_lang` is not a language-only prior.** It is pooled from post-fusion last-layer
   text tokens that already attend to the image and vary across frames. A true prior
   control is an oracle task-ID table or a pre-fusion text-only embedding.
7. **Task-ID accuracy is confounded.** Eight of ten LIBERO-10 tasks have unique scenes;
   even t0/t1 classification uses different demonstrations / actions rather than an
   identical-state intervention. `real_ll = 1.0` proves that injected prompt identity
   is accessible, not that it improves dynamics or decisions.
8. **Probe-set bookkeeping needs correction.** The stored set contains 5,258 frames,
   not ~6.5K. Recollection succeeded for 97/100 shards; three demos marked valid by the
   earlier report failed during this replay. Tasks contain 2–8 tracked objects rather
   than a fixed eight. Split IDs, current replay outcome, selected λ, moving-dim counts,
   seeds, and a dataset fingerprint should be emitted with the report.

### Required closure tests

- Fix the progress-table numbers and probe-set metadata; filter or explicitly retain
  the three failed recollections by a documented rule.
- Plot masks/heatmaps over the processed policy frame. Prefer direct post-construction
  simulator segmentation (or disjoint, object-size-aware projected masks) over fixed
  overlapping disks.
- Redefine progress from actual terminal/success time and BDDL predicates.
- Use numeric demo sorting, grouped demo/init-state CV, train-defined evaluation dims,

- Replicate the same-frame prompt battery across more states / both t0 and t1 rollout

- Run the decisive branch probes: controlled next-state prediction, predicate/progress
  prediction, and same-candidate-pool ranking under t0 vs t1.
