## Corrections discovered

### 1. Clean chain baseline

`framework_design.md` was still displaying the contaminated/audited v1 table
immediately before calling v2 the protocol of record. The clean
`results/chains/chain_exam_v2.json` values are:

| task | full SR / Q | decomp SR / Q |
|---|---:|---:|
| chain3 | 0% / 0.67 | 20% / 0.73 |
| chain4 | 0% / 0.65 | 0% / 0.70 |
| chain5 | 0% / 0.52 | 0% / 0.56 |

The full arm completes alphabet soup and tomato sauce in `15/15`, butter in
`6/15`, and neither cream cheese nor milk. The old `14/15`, butter-twice, and
cream-once counts belong to v1 and cannot describe the active baseline.

### 2. Active training default

`scripts/train_lc_flow.py` still defaults to `raw_v1`, although raw unbalanced
outcome supervision has been rejected after its predicate/continuation
shortcut. Before another run, effect-centered training must become the default
or the objective must be explicitly required.

### 3. Train aggregation does not establish broad pairing

The current evaluator calls a ratio of averaged MSEs a source macro and retains
unresolved groups in those MSE averages. Only two of four train groups have
resolved object effects:

| resolved object group | model / group-mean | cosine | matched / permutation |
|---|---:|---:|---:|
| seed 1000 | 0.090 | 0.956 | 0.046 |
| seed 1001 | 1.375 | 0.088 | 0.911 |

Thus `0.181/0.522/0.091` does not mean that object pairing was learned across
train sources. The honest result is mixed: one resolved group is learned
strongly and one is not. The dev failure remains unaffected because its only
group is resolved.

The next evaluator must report resolved per-source/group values, source pass
fractions, and aggregate ratios separately.

### 4. First-ten masking is not yet a strict credit boundary

The branch-FM loss masks positions `10:50`, but all fifty target actions first
enter π0.5's bidirectional action-token computation. The first ten predictions
can therefore depend on the unexecuted suffix. This does not directly optimize
the suffix loss, but it permits target-suffix context and weakens the claim that
branch outcomes supervise only executed actions.

Before policy attribution, the first-ten gradient should be invariant to the
unexecuted target suffix, with a regression test that changes/resamples the
suffix while holding the executed prefix fixed.

### 5. Current storage cannot perform the intended history-level language swap

The v1.1 artifacts store one full-prompt-conditioned history prefix sequence,
plus current/next observations. Because `z_t^\ell` is recurrent, this is
insufficient to compare the same complete visual-action history under another
instruction. The next schema must either:

- save raw observation/action history so every alternative language can be
  recomputed through the frozen prefix model; or
- save a complete, correctly recomputed prefix sequence for every crossed
  language.

Semantic relabel rows alone do not create a crossed-language predictive-state
experiment.

### 6. Precise language-path claim

Stock π0.5 already consumes language directly through `H_t^\ell` and the KV
cache. Therefore the valid architectural claim is not “all task information
passes through `z`.” It is:

> the new LC contribution receives no additional task-ID or proposal-prompt
> bypass around `z_t^\ell`.

Zero-LC, no-world-loss, and no-persistent-state controls are required to
attribute the incremental behavior change.

## Research-order correction

The failed v2 checkpoint does not justify a large multi-seed policy evaluation,
but the project must not turn its physical diagnostic into a permanent
prerequisite for attempting the main hypothesis. The next minimal shared-scene
pilot must combine:

```text
independent effect/noise-resolved task-object branches
                         ×
same-(history, action) compatible goals and paraphrases
                         ×
language-dependent progress/relevance and positive full-goal action targets
```

Every new checkpoint receives a cheap paired full-prompt `N=1` policy readout.
The physical/model gate controls expensive multi-seed promotion and how
strongly an improvement may be attributed to LCWM; it does not block direct
π0.5 improvement attempts.

The immediate sequence is therefore:

1. fix the active objective default, resolved-source aggregation, and suffix
   credit contract;
2. freeze source-episode train/dev/test assignments before collection;
3. collect the joint `physical × language × policy-target` shared-scene pilot;
4. train effect-centered LC-Flow with crossed semantic/consistency terms and
   demo rehearsal;
5. report controlled effects and a cheap paired `N=1` readout from the same
   checkpoint;
6. run formal multi-seed chain evaluation, retention, and attribution controls
   only for a promising checkpoint.

No architecture change is selected by this audit. LC-Flow remains the primary
candidate; the correction is to make its next data and supervision actually
exercise the language-conditioned predictive-state hypothesis while directly
attempting to improve π0.5.

# Execution (Claude) — contact-mode collection, pre-registered before running

This section executes steps 1–3 of the audit's immediate sequence. It was
written **before** the collection run started. The stall+recovery collector is
untouched; contact mode is additive (`rollout_to_contact` in
`lcwm/branch_collect.py`, new `scripts/collect_chain3_contact.py`).

## Why contact-mode (addressing "collect more of the same" from §15.7)

The audit's clean v2 numbers: the full arm completes alphabet soup and tomato
sauce **15/15** each. Both are chain3 goal atoms, so their on-policy
approach/grasp/transport/place states are **task-object interactions**
available at every seed — no off-policy recovery bridge (which failed on all
fresh seeds: 16 attempts → 3 sources). At a contact-proximal state, sibling
10-step action blocks must produce different task-object motion — precisely
the effect-resolved signal whose absence closed the model gate
(dev object ratio/cosine/matched = 2.503/−0.012/1.013).

## Pre-registered protocol

Trigger (exact): run the on-policy full-prompt rollout under the same sampling
law and noise seeds as `rollout_to_stall` (so the trajectory prefix is the
same source episode as a stall run at that seed). At each decision boundary,
compute the distance from the EEF to the root body of every goal object whose
atom is still false. Snapshot at the first decision where the minimum such
distance ≤ **0.05 m** (`--contact-skip` earlier matches passed over; this run
uses skip = 0). The nearest incomplete object becomes the group's dense-goal
object; receptacle `basket_1`; atomic proposal prompt =
`SUBGOAL_PHRASE[contact object]`.

- `collect_snapshot_group` **unchanged**: same 13-branch structure
  (1 stock_full + 4 full + 4 exact_pair + 4 remaining_atomic), execution
  horizon 10, continuations 4 × 160, restore-QC gate, admission margins
  (`dense_progress_margin = 5e-4`, `min_effect_noise_ratio = 10`).
- Contract `chain3_contact_v1_20260724`, per-seed hash in the shared
  `datasets/chain_branches_v1_1` manifest (merge-append).
- **Audit correction 5 (schema)**: each contact group additionally stores the
  raw per-decision-boundary observations of the source rollout
  (`history_observations`: images as uint8 + robot state) alongside the
  already-stored normalized action history, so that any alternative
  instruction can later be recomputed through the frozen prefix model over the
  *complete* history. This makes the crossed-language experiment possible
  offline; it does not by itself perform it.
- **Split freeze (audit step 2), fixed before collection** (mod-10 rule):
  train **1010, 1011, 1012** (new independent episodes); dev **1018** (same
  source episode as the existing dev stall group — split lock preserved) and
  **1038** (new independent dev episode); test **1039**. Excluded: 1000–1004
  (chain-exam seeds; 1000/1001 already train), 1028 (closed-loop eval seed),
  1008/1009/1019/1029 (burned attempts left as recorded).
- Source attempts: 2 per seed, noise stride 100. Failed attempts recorded in
  the manifest with a per-decision nearest-incomplete-object distance trace.
  **No threshold tuning without a written amendment here.**

Effect/noise coverage report (deliverable regardless of outcome), per group:
(1) sibling **task-object** displacement dispersion, separately from
(2) **incidental** displacement of all other tracked objects,
(3) restore-QC replay residual as the noise floor,
(4) positive flow targets, predicate flips, dense-progress branches.
A group is **effect-resolved** iff max sibling task-object displacement
≥ max(2 mm, 10 × its replay object residual).

Success condition: ≥ 3 independent train episodes each with ≥ 1
effect-resolved group; ≥ 1 effect-resolved dev group; ≥ 1 test group. Any
seed failure is reported before substituting seeds.

## Scope guard

- Contact groups supply the **physical factor** of the audit's joint pilot
  (independent effect/noise-resolved task-object branches) plus the raw
  history needed for the language factors. Compatible-goal/paraphrase labels
  and language-dependent progress are offline label construction on the stored
  data (object positions for all tracked objects and the basket are stored,
  so per-goal progress for any instruction is computable) — a separate step,
  not claimed here.
- H1 (data): sibling blocks at contact states produce above-noise task-object
  effect dispersion. Disconfirmed if admitted groups fail effect-resolution.
- H2 (model): effect-centered v2 on expanded data passes the **unchanged**
  §15.10 promotion rule. If not, next step is diagnosis, not threshold edits.

## Pre-registered downstream sequence (= audit steps 1, 4–6)

1. Audit step-1 fixes, done while collection runs in background: (a) the
   trainer's active objective defaults to effect-centered or hard-requires an
   explicit choice; (b) evaluator reports resolved-only per-source values and
   pass fractions separately from aggregates; (c) suffix credit contract —
   branch targets enter the flow graph with the unexecuted suffix replaced by
   a branch-independent constant, plus a regression test that resamples the
   suffix and asserts unchanged first-ten losses/gradients.
2. Re-fit v2 σ_b scales (same formula/averaging) on the expanded selected
   train artifacts; retrain effect-centered v2, same trainer and rotation.
3. Gates via `eval_lc_flow_outcomes.py` (unchanged promotion rule) **and** the
   audit's cheap paired full-prompt N=1 readout from the same checkpoint —
   the readout is reported either way; the gate controls multi-seed promotion
   and attribution strength, not the attempt.
4. Multi-seed chain evaluation, retention (requires demo rehearsal), and
   matched no-dynamics controls only for a promising checkpoint.

### AMENDMENT 1 (written before rerun; needs review-agent sign-off)

Contact-contract admission changes from `restore_qc.valid` (structural AND
q_resolved AND object_resolved) to **`structural_valid AND object_resolved`**.

Rationale: the group-level AND-gate is redundant with the per-channel
machinery that already exists downstream — `q_resolved`/`object_resolved`
are stored per group, `eval_lc_flow_outcomes.py` gates every channel's
metrics on per-group resolution, and the v2 scale fit floors σ_b at 3× replay
dispersion. Discarding a group whose object channel is perfectly resolved
because its q channel sits at 9.75× (vs 10.0×) noise throws away exactly the
data §15.10 demands, while keeping it adds no unresolved supervision: the q
channel's False flag travels with the group. This is a per-channel admission
argument, not a threshold change — both thresholds stay as registered.
Recorded in the contract as `admission_rule`; contract version bumped to
`chain3_contact_v1_1_20260724` so amended groups are distinguishable by hash.
The strict-gate rejection artifact remains in `rejected/` as the record of
the unamended outcome.
