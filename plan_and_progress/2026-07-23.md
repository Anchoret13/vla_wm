# Progress — 2026-07-23 (direct policy-improvement pivot)

## FIRST PRINCIPLE — why this project exists

> **Improve the VLA by giving it a better learned understanding of real-world
> dynamics.**

Everything else is subordinate to this objective:

- language conditioning tells the model **which physical distinctions matter**
  for the current task;
- the persistent latent is the representation in which that understanding is
  retained;
- branch data makes action-conditioned physical consequences identifiable;
- outcome heads ground the state in what actually changes in the world;
- π0.5 integration tests whether this understanding produces better actions;
- LoHo-style performance is the downstream test, not a substitute for dynamics.

The intended causal chain is:

```text
same real state + different executed actions
                       ↓
different physical futures observed in branch data
                       ↓
LC state/transition predicts those controlled effects
                       ↓
the predictive state changes π0.5's flow field
                       ↓
better closed-loop VLA behavior
```

Language must not turn the system into a task-code, phase, or remaining-goal
lookup table. Conversely, policy improvement obtained only from better action
labels, extra parameters, prompt decomposition, or branch imitation is useful
engineering evidence but is **not yet evidence for the project hypothesis**.

Therefore Phase 1 has two coupled bars:

1. **Engineering bar:** LC-Flow improves full-prompt chained-task Q/SR while
   retaining standard LIBERO-10 competence.
2. **Scientific bar:** held-out controlled physical/task effects are predicted,
   and matched no-dynamics controls do not explain the whole policy gain.

An experiment is prioritized only when it strengthens or tests at least one link
in this chain. Diagnostics remain supporting measurements; they should neither
replace the closed-loop test nor drift into unrelated representation analysis.

## Bottom line

The previous plan serialized data/model diagnostics ahead of the main research
test. Those diagnostics remain useful, but they are now supporting measurements
and later ablations rather than prerequisites.

> **PRIMARY EXPERIMENT:** modify π0.5 so that a persistent
> language-conditioned predictive state directly conditions its flow-matching
> action expert, train the resulting action distribution from outcome-labeled
> branches, and test whether it improves closed-loop chained-exam performance.

The Phase-1 endpoint is the full composite instruction, no oracle predicate or
current-subgoal input, one generated action chunk per decision (`N = 1`), and a
paired held-out comparison against stock π0.5. Best-of-N reranking may help us
collect data and bootstrap learning, but it is no longer the main claim.

This is a direct test of the project hypothesis:

```text
same physical observation/action history
                    +
different task language
                    ↓
different task-relevant predictive state
                    ↓
different π0.5 flow field / action distribution
                    ↓
better long-horizon behavior
```

The state is not accepted because its latent vectors separate. It is useful only
if the separation changes predicted task outcomes and ultimately improves the
policy through action-conditioned predictive information.


   `success = true`, all goal bits, and `Q = 1`;
4. rerun at least the affected decomp cells and regenerate the aggregate table.

## Active architecture — LC-Flow π0.5

At each decision boundary (`c = 10`):

\[
H_t^\ell = \operatorname{PrefixVLM}(o_t,\ell),
\]

\[
\bar z_t^\ell =
T_\theta\!\left(
z_{t-1}^\ell,
E_a(a^{\mathrm{exec}}_{t-1,0:10})
\right),
\qquad
z_t^\ell =
U_\theta(\bar z_t^\ell,H_t^\ell).
\]

`z_t^\ell` is a persistent task-relevant predictive state. It is carried across
decision steps and cleared only on episode reset:

- `T` is an action-conditioned predictive prior;
- `U` corrects that prior from the new observation and language-conditioned
  prefix state;
- language enters through the real prompt prefix hidden state;
- `T` does not receive a second explicit language/task-ID bypass.

This retains action history without restoring the old `a_prev` target shortcut:
the previous executed block is used to predict the current prior, not concatenated
as an easy answer for the next-action target.

The π0.5 action expert becomes:

\[
v_\psi(x_\tau,\tau\mid H_t^\ell,z_t^\ell).
\]

The minimal first injection reuses the action expert's existing AdaRMS
conditioning:

\[
c_{\mathrm{expert}}
=
c_{\mathrm{time}}
+
W_z\operatorname{Pool}(z_t^\ell).
\]

`W_z` is zero-initialized. Before training, LC-Flow therefore reproduces stock
π0.5 exactly without changing token positions or prefix-cache semantics. The
existing prefix forward already returns the prefix hidden state and KV cache in
one pass, so the same 3B-prefix computation can update `z_t^\ell` and condition
action generation.

For an executed candidate branch:

\[
\hat z_{t+1}^{\ell,i}
=
T_\theta\!\left(
z_t^\ell,E_a(a^{(i)}_{0:10})
\right),
\]

\[
D_\theta(\hat z_{t+1}^{\ell,i})
=
\left(
\widehat{\Delta \mathrm{physical}}^{\,i},
\widehat{\Delta \mathrm{predicate}}^{\,\ell,i},
\widehat{\Delta \mathrm{progress}}^{\,\ell,i},
\widehat R^{\,\ell,i}
\right).
\]

The physical outcome should remain stable under an instruction swap; predicate,
progress, and return readouts may change with the task. These heads ground the
state. The induced policy improvement is the downstream endpoint, while correct
controlled-effect prediction establishes that the information influencing the
policy is an understanding of dynamics rather than only task memory.

### Initial trainable scope

- initially frozen: π0.5 PrefixVLM / 2B vision-language trunk;
- trainable: LC state, action encoder, `T`, `U`, outcome heads, and zero-init
  AdaRMS state projection;
- action expert: start through the learned conditioning adapter, then unfreeze or
  use PEFT only if the adapter cannot move the distribution enough.

This is not “a frozen π0.5 plus an external world-model scorer.” It is one policy
whose learned predictive state changes the flow-matching action distribution.

## Direct branch supervision

Initial data come from late-chain stall and recovery states, because those are
where the current policy's task prior becomes wrong. For each snapshot, proposals
may come from:

- the full composite chain instruction;
- the exact in-distribution pair prompt for the scene;
- compatible atomic remaining-goal prompts;
- multiple saved flow-noise samples.

Every branch is evaluated and relabeled under the **full composite goal**.
`proposal_prompt / proposal_goal_id` is provenance only; it must not become an
input shortcut. We store the full 50-action proposal, execute and outcome-label
the first 10 actions, and optionally continue a subset for longer-return labels.
All siblings from one snapshot remain in one data split, and exact flow noise is
saved because environment seed alone does not fix policy sampling noise.

All branches train the transition and outcome model, including failures. Only
positive-progress or within-snapshot superior branches train the action
distribution:

\[
\mathcal L_{\mathrm{branch\text{-}FM}}
=
w_i
\left\|
M_{0:10}\odot
\left[
v_\psi(x_\tau,\tau,H_t^\ell,z_t^\ell)
-
(\epsilon-a_i)
\right]
\right\|^2.
\]

`M_{0:10}` is required: the branch outcome verifies only the ten executed actions,
so the unexecuted remaining forty may not inherit the label. Negative branches
teach the outcome model what fails; they are not reverse-imitation targets.
Original LIBERO demonstrations retain their normal full-chunk flow-matching loss
and are mixed into training to preserve the existing manipulation skills.

The action loss consumes the branch data, but it must not become the entire
method. `T/U/z` are trained and evaluated on held-out controlled effects:
proprioceptive change, object displacement/contact, predicate flips, and
task-relative progress under the executed action block. If branch-weighted flow
training without these predictive losses matches LC-Flow, then the observed
policy gain is behavior distillation—not yet evidence that world-dynamics
understanding improved the VLA.

The first collection is deliberately small: roughly 128–256 useful stall/recovery
snapshots, not a large dataset built before learning starts. Collection, joint
training, and closed-loop evaluation form one iteration; a second on-policy /
DAgger-style collection follows only if the first policy exposes new failure
states.

| negative branch misuse | failed branches are informative but are not desirable actions | negative-weight imitation is not a valid inverse of behavior cloning | **design-critical**; use failures for transition/outcome learning, not as action targets |
| missing training path | current π0.5 loss has per-sample error but no branch-quality weighter or first-10 mask | branch outcomes cannot yet safely update the action expert | **open implementation work** before joint branch training |
| proposal-language leakage | atomic/pair prompts expand action support | feeding proposal identity to the learner reintroduces oracle subgoal supervision | **design-critical**; store it as provenance and train/evaluate under the full goal |
| task-code copying | recurrence can carry a static language code and separate latents | different latents alone do not demonstrate predictive conditioning | **open model risk**; require controlled outcome effects and policy improvement |
| shared-physics corruption | language-conditioned rollouts may predict different physical futures for the same state/action | that would model language as changing physics rather than relevance | **open model risk**; physical-effect head plus cross-language consistency |
| dynamics attribution | branch-FM or extra adapter capacity may improve actions without using learned dynamics | performance alone would not establish the project's central mechanism | **claim constraint**; held-out controlled effects plus matched no-dynamics/no-world-loss controls |
| insufficient policy control | zero-init AdaRMS may be too weak with the action expert frozen | the state may learn without moving the action distribution enough | **open implementation risk**; measure action shift, then PEFT/unfreeze by rule |
| reranking-only success | best-of-N can improve selection while leaving the action distribution unchanged | it would not show that LC state improved π0.5 itself | **claim constraint**; full-prompt direct `N = 1` is primary |
| retention / no-op regression | branch updates can forget skills, and a zero-init extension can still be wired incorrectly | a chain gain may trade away stock competence or start from a changed baseline | **open implementation risk**; demo rehearsal, LIBERO-10 retention, and a fixed-noise stock-equivalence test before training |
| narrow evaluation | current chains use one scene family and five seeds/cell | an improvement can be scene- or seed-specific | **scope limit**; held-out seeds first and cross-scene replication after the vertical slice |

1. continuation return depends on the continuation policy, so the first target is

2. the corrected decomp result shows goal/progress routing can help, while the

## Primary experiment and controls

Primary comparison:

```text
stock π0.5, N=1
        versus
LC-Flow π0.5, N=1
```

Locked evaluation contract:

- one full composite instruction for the whole episode;
- no oracle predicates, decomposition, or current-subgoal input;
- one action-chunk sample per decision and execute its first 10 actions;
- held-out snapshot groups and held-out evaluation seeds;
- chain3 first, then chain4/5;
- report SR, Q-score, per-atom completion times/timelines, and standard
  LIBERO-10 retention.

The most useful matched controls remain:

1. corrected oracle-decomposition reference;
2. branch-weighted flow training without a persistent LC state;
3. LC-Flow with matched state/adapter capacity but without world/outcome losses;
4. LC-Flow with best-of-8/16 reranking as a bootstrap/headroom result;
5. matched readout-only conditioning after the first vertical slice.

These controls explain *why* the main system works or fails. They do not have to
be completed before attempting the primary system, but controls 2–3 are required
before attributing a final gain to dynamics understanding.
