# Progress — 2026-07-23 (direct policy-improvement pivot)

## FIRST PRINCIPLE — why this project exists

> **Improve the VLA by giving it a better learned understanding of real-world
> dynamics.**

Everything else is subordinate to this objective:

- language conditioning tells the model **which physical distinctions matter**
  for the current task;
- the persistent latent is the representation in which that understanding is
  retained;
- branch data makes action-conditioned physical consequences identifiable;
- outcome heads ground the state in what actually changes in the world;
- π0.5 integration tests whether this understanding produces better actions;
- LoHo-style performance is the downstream test, not a substitute for dynamics.

The intended causal chain is:

```text
same real state + different executed actions
                       ↓
different physical futures observed in branch data
                       ↓
LC state/transition predicts those controlled effects
                       ↓
the predictive state changes π0.5's flow field
                       ↓
better closed-loop VLA behavior
```

Language must not turn the system into a task-code, phase, or remaining-goal
lookup table. Conversely, policy improvement obtained only from better action
labels, extra parameters, prompt decomposition, or branch imitation is useful
engineering evidence but is **not yet evidence for the project hypothesis**.

Therefore Phase 1 has two coupled bars:

1. **Engineering bar:** LC-Flow improves full-prompt chained-task Q/SR while
   retaining standard LIBERO-10 competence.
2. **Scientific bar:** held-out controlled physical/task effects are predicted,
   and matched no-dynamics controls do not explain the whole policy gain.

An experiment is prioritized only when it strengthens or tests at least one link
in this chain. Diagnostics remain supporting measurements; they should neither
replace the closed-loop test nor drift into unrelated representation analysis.

## Bottom line

The previous plan serialized data/model diagnostics ahead of the main research
test. Those diagnostics remain useful, but they are now supporting measurements
and later ablations rather than prerequisites.

> **PRIMARY EXPERIMENT:** modify π0.5 so that a persistent
> language-conditioned predictive state directly conditions its flow-matching
> action expert, train the resulting action distribution from outcome-labeled
> branches, and test whether it improves closed-loop chained-exam performance.

The Phase-1 endpoint is the full composite instruction, no oracle predicate or
current-subgoal input, one generated action chunk per decision (`N = 1`), and a
paired held-out comparison against stock π0.5. Best-of-N reranking may help us
collect data and bootstrap learning, but it is no longer the main claim.

This is a direct test of the project hypothesis:

```text
same physical observation/action history
                    +
different task language
                    ↓
different task-relevant predictive state
                    ↓
different π0.5 flow field / action distribution
                    ↓
better long-horizon behavior
```

The state is not accepted because its latent vectors separate. It is useful only
if the separation changes predicted task outcomes and ultimately improves the
policy through action-conditioned predictive information.

## Active architecture — LC-Flow π0.5

At each decision boundary (`c = 10`):

\[
H_t^\ell = \operatorname{PrefixVLM}(o_t,\ell),
\]

\[
\bar z_t^\ell =
T_\theta\!\left(
z_{t-1}^\ell,
E_a(a^{\mathrm{exec}}_{t-1,0:10})
\right),
\qquad
z_t^\ell =
U_\theta(\bar z_t^\ell,H_t^\ell).
\]

`z_t^\ell` is a persistent task-relevant predictive state. It is carried across
decision steps and cleared only on episode reset:

- `T` is an action-conditioned predictive prior;
- `U` corrects that prior from the new observation and language-conditioned
  prefix state;
- language enters through the real prompt prefix hidden state;
- `T` does not receive a second explicit language/task-ID bypass.

This retains action history without restoring the old `a_prev` target shortcut:
the previous executed block is used to predict the current prior, not concatenated
as an easy answer for the next-action target.

The π0.5 action expert becomes:

\[
v_\psi(x_\tau,\tau\mid H_t^\ell,z_t^\ell).
\]

The minimal first injection reuses the action expert's existing AdaRMS
conditioning:

\[
c_{\mathrm{expert}}
=
c_{\mathrm{time}}
+
W_z\operatorname{Pool}(z_t^\ell).
\]

`W_z` is zero-initialized. Before training, LC-Flow therefore reproduces stock
π0.5 exactly without changing token positions or prefix-cache semantics. The
existing prefix forward already returns the prefix hidden state and KV cache in
one pass, so the same 3B-prefix computation can update `z_t^\ell` and condition
action generation.

For an executed candidate branch:

\[
\hat z_{t+1}^{\ell,i}
=
T_\theta\!\left(
z_t^\ell,E_a(a^{(i)}_{0:10})
\right),
\]

\[
D_\theta(\hat z_{t+1}^{\ell,i})
=
\left(
\widehat{\Delta \mathrm{physical}}^{\,i},
\widehat{\Delta \mathrm{predicate}}^{\,\ell,i},
\widehat{\Delta \mathrm{progress}}^{\,\ell,i},
\widehat R^{\,\ell,i}
\right).
\]

The physical outcome should remain stable under an instruction swap; predicate,
progress, and return readouts may change with the task. These heads ground the
state. The induced policy improvement is the downstream endpoint, while correct
controlled-effect prediction establishes that the information influencing the
policy is an understanding of dynamics rather than only task memory.

### Initial trainable scope

- initially frozen: π0.5 PrefixVLM / 2B vision-language trunk;
- trainable: LC state, action encoder, `T`, `U`, outcome heads, and zero-init
  AdaRMS state projection;
- action expert: start through the learned conditioning adapter, then unfreeze or
  use PEFT only if the adapter cannot move the distribution enough.

This is not “a frozen π0.5 plus an external world-model scorer.” It is one policy
whose learned predictive state changes the flow-matching action distribution.

## Direct branch supervision

Initial data come from late-chain stall and recovery states, because those are
where the current policy's task prior becomes wrong. For each snapshot, proposals
may come from:

- the full composite chain instruction;
- the exact in-distribution pair prompt for the scene;
- compatible atomic remaining-goal prompts;
- multiple saved flow-noise samples.

Every branch is evaluated and relabeled under the **full composite goal**.
`proposal_prompt / proposal_goal_id` is provenance only; it must not become an
input shortcut. We store the full 50-action proposal, execute and outcome-label
the first 10 actions, and optionally continue a subset for longer-return labels.
All siblings from one snapshot remain in one data split, and exact flow noise is
saved because environment seed alone does not fix policy sampling noise.

All branches train the transition and outcome model, including failures. Only
positive-progress or within-snapshot superior branches train the action
distribution:

\[
\mathcal L_{\mathrm{branch\text{-}FM}}
=
w_i
\left\|
M_{0:10}\odot
\left[
v_\psi(x_\tau,\tau,H_t^\ell,z_t^\ell)
-
(\epsilon-a_i)
\right]
\right\|^2.
\]

`M_{0:10}` is required: the branch outcome verifies only the ten executed actions,
so the unexecuted remaining forty may not inherit the label. Negative branches
teach the outcome model what fails; they are not reverse-imitation targets.
Original LIBERO demonstrations must retain their normal full-chunk flow-matching
loss and be mixed into scaled training to preserve the existing manipulation
skills. This rehearsal path is not active in the current one-group trainer, so
no retention claim can yet be made.

The action loss consumes the branch data, but it must not become the entire
method. `T/U/z` are trained and evaluated on held-out controlled effects:
proprioceptive change, object displacement/contact, predicate flips, and
task-relative progress under the executed action block. If branch-weighted flow
training without these predictive losses matches LC-Flow, then the observed
policy gain is behavior distillation—not yet evidence that world-dynamics
understanding improved the VLA.

The first collection is staged: one corrected v1.1 smoke, then roughly 16 useful
stall/recovery groups before any 128–256-group scale-up. Collection, joint
training, and closed-loop evaluation form one iteration; a second on-policy /
DAgger-style collection follows only if the first policy exposes new failure
states.

These controls explain *why* the main system works or fails. They do not have to
be completed before attempting the primary system, but controls 2–3 are required
before attributing a final gain to dynamics understanding.

## HISTORICAL CHECKPOINT: §15.4b LC-Flow vertical slice v1.1 before execution

The eight-branch file above remains the historical `lcwm_chain_branch_v1`
result. It must not be silently reused by the new trainer: it has no natural
continuation-vs-restore QC, no exact proposal-noise tensors, no replayable
branch-next states, and no positive flow target. The corrected collector writes
to a separate `chain_branches_v1_1` root.

What is now implemented:

- `LCState` is a persistent full-instruction state. `T` sees the previously
  executed normalized action block and an explicit execution mask; language
  enters through the real-prompt prefix consumed by `U`, not through an oracle
  task ID or direct transition bypass.
- A zero-initialized `W_z` enters the frozen π0.5 action expert through its
  AdaRMS condition. The runtime and training APIs pass this bias explicitly;
  the old mutable `_lc_bias` wrapper is retained only as a deprecated smoke
  artifact.
- Flow loss preserves `[branch, 50, 7]`, masks every loss element after the
  actual executed length (at most ten), and never applies negative imitation
  weights. `T` receives only executed actions. The mask prevents direct
  branch-FM credit on the other forty tokens, but those suffix tokens remain
  inside the expert's joint computation and can still affect its first-ten
  predictions; causal tail removal is not implemented.
- The frozen PrefixVLM runs once per snapshot. Its KV cache is reused by
  microbatched action-expert flow training; the current full-prompt hidden state
  used by `U` comes from that same prefix pass.
- Each group stores the stock reference plus four full, four exact-pair, and
  four remaining-atomic proposals; exact Gaussian proposal-noise tensors and
  seeds; normalized and executed actions; first-ten q/object/predicate effects;
  next observations, simulator states, terminal fields, and next full-prompt
  prefixes.
- Snapshot admission compares the uninterrupted stock continuation with two
  restored executions. Structural mismatches are rejected. A physical channel
  is admitted only if replay dispersion passes an absolute tolerance or the
  cross-action effect is at least ten times replay noise; the v18 result below
  shows why bit-exact proprio restore cannot currently be claimed.
- The main continuation label is completion of the **full composite goal**.
  Atomic success is auxiliary. Only four deterministic branches receive the
  expensive paired continuation, using a common prompt, horizon, and flow-noise
  schedule.
- The old immediate 2/3 stall produced no object motion. The successful v18
  state miner samples four chunks per recovery block from a compatible
  cream-cheese+butter prompt for up to sixteen blocks and stops within `0.16 m`
  of cream cheese, while recomputing every stored state prefix under the full
  composite instruction. This is an empirical offline collection heuristic.
  Behavior-prompt identity, seeds, and selection scores are provenance and are
  not supplied to the learner.
- All branches, including failures, train controlled physical/semantic outcome
  heads. Branch-FM targets are non-damaging branches with immediate full-goal
  improvement or a paired full-goal continuation success/time advantage over
  stock. This is an offline action-distribution training signal for the primary
  `N=1` policy, not a final branch-ranking objective.
- `train_lc_flow.py` performs one optimizer item per sibling group, full-history
  forward with truncated BPTT, outcome learning on every branch, positive-only
  flow microbatches, explicit base freezing, gradient checks, adapter-only
  checkpoints, and held-out outcome evaluation.

CPU/interface verification now passes **39 targeted tests**: evaluator terminal
capture, environment-clock snapshot restore, grouped schema/splits, exact
execution masks, padded-prefix invariance, early-terminal transition masking,
outcome masks, recurrent history semantics, adapter round-trip, and collector
selection/storage helpers.

This checkpoint is superseded by §15.4c–§15.9. Native `N=1` parity, zero-init
no-op, prefix-once loss parity, real frozen-expert gradient flow, one v1.1

## §15.7 collection scale-out — five groups reveal a coverage bottleneck

The collector was extended before more GPU time was spent:

- a source episode now has up to four full-prompt rollout attempts with explicit
  noise seeds and a stable source-episode split;
- every attempt, including a failed state-mining attempt, is recorded in the
  manifest instead of disappearing;
- group publication is atomic and an existing file is loaded and validated
  before it can be skipped;
- filenames include the collection-contract fingerprint, and training records
  exact selected artifact hashes, the manifest hash, and one aggregate training
  source hash;
- recovery-state mining keeps the best safe state along the route instead of
  blindly using the final state. The current development heuristic admits a
  best pair-route state within `25 cm`, then applies one remaining-goal recovery
  block by default and requires target motion or a final distance within
  `10 cm`;
- if state mining itself discovers a target-effect action, the collector can
  preserve that exact action/noise as an optional fourteenth sibling. This path
  is implemented and tested but has not yet occurred in an admitted real group.

object/progress remain
`7.31×/1.66×` worse. The problem is not only dev extrapolation.

This result is a successful integration/trainability test and a failed
model-learning test. It proves that the zero-init gate opens, a seen branch-FM
target can be fitted, and the adapter can move π0.5 actions. It does not prove
held-out dynamics, useful hidden state, crossed-language conditioning, or a
better policy. The failure is directly relevant to the main implementation:
equal-weight raw losses put binary phase/return shortcuts orders of magnitude
above millimeter-scale physical effects.

The next model iteration should therefore:

1. make the primary physical target the normalized, symmetric
   branch-mean-centered effect `C_N y`; keep stock-relative effects for policy
   advantage/flow weighting and absolute prediction as an audit;
2. report zero-effect and group-mean baselines for every continuous head;
3. train/evaluate predicate **flips**, not aggregate next-state F1/BCE, and

4. keep absolute-progress and relative-to-stock flow targets as separate
   coverage strata;
5. add independent effectful source episodes and at least one held-out positive
   action group before interpreting another aggregate loss curve.

This is not a hypothesis detour. It changes the main LC-Flow supervision so the
learned state must encode action-conditioned consequences instead of phase
constants.

## §15.10 effect-centered v2 pilot — real q-effect signal, object transfer fails

The loss correction proposed in §15.8 has now been implemented and run. The
LC-Flow architecture is unchanged. For each sibling group with `N` candidate
actions, v2 trains continuous action effects after removing the shared branch
mean:

\[
C_N=I-\frac{1}{N}\mathbf 1\mathbf 1^\top,\qquad
\mathcal L_b=
\operatorname{MSE}\!\left(
\frac{C_N\hat y_b-C_Ny_b}{\sigma_b}
\right).
\]

This is equivalent to matching all pairwise sibling action-outcome
differences. Any action-independent state/phase constant is canceled exactly.
The five equal-weight blocks are EEF position, quaternion components, gripper
qpos, valid object xyz, and normalized dense progress. `next_bits` and
continuation BCE are excluded and their heads frozen because the current data
contains no predicate flip and no successful continuation.

Scales are fit only on selected train artifacts, first averaging groups within
each source episode and then averaging source episodes:

\[
\sigma_b=\max\!\left(
\sqrt{\operatorname{Var}_{train}(C_Ny_b)},
3\sqrt{\operatorname{Var}_{replay}(y_b)},
\tau_b
\right).
\]

The locked scales are:

| block | scale |
|---|---:|
| EEF position | `7.344e-3 m` |
| quaternion components | `5.451e-3` |
| gripper qpos | `2.598e-4` |
| object position | `1.175e-3 m` |
| normalized dense progress | `1.055e-3` |

Continuous output layers start at zero effect. Each epoch samples one rotating
group per independent source episode, so the three correlated seed-1001 groups
do not outvote seed 1000. Branch-FM remains the same positive-only first-ten
auxiliary at weight `0.1`. The run uses 15 epochs / 30 optimizer steps and is
stored in `results/lc_flow_chain3_effect_v2_pilot`. The selected-data manifest
hash is
`044502ff45dc09d61a99f25259572491292bc9a60d051bf5ae71b08f8af9f881`,
training-source hash is
`071f09eb821f7a038e2e97154eb62c8f89e8a3f2583e39d3ad304d692b3c7199`,
and final adapter SHA-256 is
`a142ab9ab5cc253a7c76c8000820ba0960b66401e8fadad0c51b8a0b687f69af`.

The provisional promotion rule was fixed before reading the run:

- held-out q and object centered-model/group-mean ratios `<= 0.8`;
- q and object centered cosine `> 0.2`;
- matched centered loss `<= 0.9 ×` deterministic permutation loss;
- progress is not scored when the held-out target has zero dispersion.

Train-split source-macro diagnostics show that v2 is learning actual
action-outcome pairing, not another constant:

| train centered audit | q | object | progress |
|---|---:|---:|---:|
| model / oracle group-mean variance | **0.487** | **0.181** | **0.766** |
| centered cosine | **0.690** | **0.522** | **0.430** |
| matched / cyclic-permutation loss | **0.374** | **0.091** | **0.652** |

On the single independent dev source, the result is partial:

| dev centered audit | q | object |
|---|---:|---:|
| model / oracle group-mean variance | `0.885` | **`2.503`** |
| centered cosine | `0.340` | **`-0.012`** |
| matched / cyclic-permutation loss | `0.761` | **`1.013`** |
| promotion | fail ratio | fail all three |

The q aggregate contains heterogeneous behavior. Relative to its zero-effect
normalized baseline, EEF position improves to `0.307×`, quaternion to
`0.901×`, while gripper is `1.012×` and does not improve. The single scalar dev
effect objective is consequently dominated by an out-of-train-scale gripper
block (`~493` at zero prediction) and should not replace block-level reporting.
Object prediction becomes worse than the action-agnostic diagnostic and does
not preserve the observed pairing.

The fixed seen-group probe confirms optimization but is not the decision:

```text

positive branch-FM          0.1910 -> 0.0277
first-10 mean action shift  0      -> 0.1508
peak GPU memory                      9.67 GB
```

This is materially stronger than v1: centered q/object/progress effects are

fails the model-learning gate because held-out object dynamics do not
generalize and q misses the `0.8` ratio threshold. Therefore this checkpoint is
**not** sent to another closed-loop run; doing so would again test an adapter
whose claimed world-model signal is incomplete.

The next action is no longer another loss/epoch sweep on seed 1018. We need
independent, effect/noise-resolved object interactions in train and locked dev,
with task object/receptacle effects reported separately from incidental object
motion. Branch-mean centering remains the symmetric dynamics loss; the stock
branch remains the reference for policy advantage/flow weighting. Absolute
physical prediction stays an audit for v2 and may return only as a small
normalized anchor after centered held-out effects pass. Crossed language is
still absent and remains a later requirement for the LCWM claim.
